# v0.24.2c.3 — Version markers + bisect flag visibility

Small, targeted ship to make future bisect data fully interpretable.

## Two problems this fixes

### 1. The shadow bisect knobs weren't being printed in run_summaries.txt

Even though `UNENDLICH_SHADOW_CASCADES` and `UNENDLICH_SHADOW_LEGACY_FB` were being *read* by the renderer (and applied — the perf numbers vary across runs that set them differently), they weren't in the `Flags in effect` block written to the file. So you couldn't tell from a saved run-summary which bisect configuration produced which perf data.

**Fixed**: both flags are now registered in `runtime_flags::flags()`, so they appear in the summary header alongside `UNENDLICH_RENDER_DISTANCE` and friends. Tests pin this:

- `flags_summary_includes_shadow_bisect_knobs` — both flag names appear in the summary text.
- `flags_summary_reports_shadow_bisect_set_values` — setting them shows the actual values, not `(default: …)`.

### 2. No version boundaries in run_summaries.txt

The file accumulated runs across versions but had no way to scan to "where did v0.24.2-c.3 start". This ship adds visual markers that bracket each version's runs:

```
======================================================================
==== VERSION 0.24.2-c.2 START 2026-05-11T13:00:00Z ====
======================================================================

==== RUN START 2026-05-11T13:00:01Z ====
version: 0.24.2-c.2
...
==== RUN END 2026-05-11T13:00:30Z ====

==== RUN START 2026-05-11T13:01:00Z ====
version: 0.24.2-c.2
...
==== RUN END 2026-05-11T13:01:25Z ====

======================================================================
==== VERSION 0.24.2-c.2 END 2026-05-11T14:00:00Z ====
======================================================================

======================================================================
==== VERSION 0.24.2-c.3 START 2026-05-11T14:00:00Z ====
======================================================================

==== RUN START 2026-05-11T14:00:01Z ====
version: 0.24.2-c.3
...
```

The 70-char `=====` rules above and below each marker make the boundaries obvious in `less` and `cat`.

## Algorithm

When `RunBlock::append` is called, before writing the run block, it scans the file for the most recent `==== VERSION X START ====` line and compares to `self.version`. Four cases:

| File state | Action |
|---|---|
| File missing / empty | Emit `VERSION X START` then the run block. |
| File has markers, latest START is same version | No extra markers (continuation). |
| File has markers, latest START is different version | Emit `VERSION old END` then `VERSION new START` then run block. |
| File has runs but **no markers** (pre-c.3 file), latest `version:` line matches current | Emit `VERSION X START` only (silently begin marking). |
| File has runs but **no markers**, latest `version:` line differs | Emit `VERSION old END (retroactive)` then `VERSION new START`. |

The last case is what happens automatically when a user with a v0.24.2-c.2-built `run_summaries.txt` first runs the v0.24.2-c.3 binary. The retroactive END gets a timestamp equal to the start-of-this-new-run (since we don't know when the prior version actually stopped). The "(retroactive)" annotation in the END line makes it clear to a reader that the timestamp is informational, not literal.

## Useful greps

- All version boundaries:
  ```
  grep "^==== VERSION" run_summaries.txt
  ```

- All run starts within v0.24.2-c.3:
  ```
  awk '/^==== VERSION 0.24.2-c.3 START/,/^==== VERSION 0.24.2-c.3 END/' run_summaries.txt | grep "^==== RUN START"
  ```

- Extract one version's worth of runs:
  ```
  awk '/^==== VERSION 0.24.2-c.3 START/,/^==== VERSION 0.24.2-c.3 END/' run_summaries.txt > v0.24.2-c.3-runs.txt
  ```

- Compare two configurations' shadow timing:
  ```
  awk '/^==== RUN START/,/^==== RUN END/' run_summaries.txt | grep -E "(SHADOW_CASCADES|^  shadow )"
  ```

## What this means for the bisect

Your next playtest sequence will be self-documenting. Each run block in `run_summaries.txt` will contain:

```
env:
  Flags in effect (binary=unendlich-world):
    UNENDLICH_RENDER_DISTANCE = 8
    UNENDLICH_SHADOW_CASCADES = 4
    UNENDLICH_SHADOW_LEGACY_FB = 0
    ...
```

So you (or I, weeks from now) can read the saved file and know exactly which configuration produced which performance. The four bisect configurations are still:

```bash
# config 1 (default, closest to v0.24.2b)
UNENDLICH_SHADOW_CASCADES=1 UNENDLICH_SHADOW_LEGACY_FB=1 ...

# config 2
UNENDLICH_SHADOW_CASCADES=1 UNENDLICH_SHADOW_LEGACY_FB=0 ...

# config 3
UNENDLICH_SHADOW_CASCADES=4 UNENDLICH_SHADOW_LEGACY_FB=1 ...

# config 4 (full v0.24.2c, known broken)
UNENDLICH_SHADOW_CASCADES=4 UNENDLICH_SHADOW_LEGACY_FB=0 ...
```

When you run these, each will deposit a self-documenting block under `==== VERSION 0.24.2-c.3 START ====`.
