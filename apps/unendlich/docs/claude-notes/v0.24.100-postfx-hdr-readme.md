# v0.24.100 — post-FX increment 1b: HDR scene buffer (R16G16B16A16_SFLOAT)

Gated behind `UNENDLICH_POSTFX` (default off ⇒ byte-identical to today). The
offscreen scene target becomes a linear **HDR float** image. Still meant to look
**identical** — `present.frag` continues to copy, and `chunk.frag` still
tonemaps into [0,1]; the HDR headroom is unused until 1c moves the tonemap out.
This is the step that gives bloom/SSR a real HDR buffer to work from.

## What changed (all POSTFX-gated)
- `postfx.rs`: offscreen color format is now `PostFx::SCENE_HDR_FORMAT =
  R16G16B16A16_SFLOAT` (a mandatory color-attachment + linear-sampled format, so
  no capability query). The offscreen render pass and the offscreen target (in
  both `new` and `recreate`) use it. The **present** pass stays swapchain-format
  (it writes the swapchain). Added a `scene_render_pass()` accessor.
- `world_renderer.rs`: because the offscreen color format now differs from the
  swapchain, the chunk and entity pipelines must be **render-pass-compatible**
  with the pass they draw into, so under post-FX they are built against the
  offscreen pass instead of the swapchain pass. Without post-FX, unchanged.

## Why it stays identical
Both scene pipelines are opaque (`blend_enable = false`), so there is no
alpha-blend-in-linear-vs-sRGB difference. The path is:

`chunk.frag` (linear, tonemapped to [0,1]) → store in RGBA16F (no encode) →
`present.frag` samples (linear) → write to sRGB swapchain (hardware encodes).

That reaches the screen with the same value as the previous sRGB-offscreen path
(`encode → sample-decode → re-encode`), except the offscreen now keeps full float
precision instead of 8-bit sRGB. egui is untouched — it already composites in the
present pass (v0.24.99), so the UI is not in this buffer.

Pipelines use dynamic viewport/scissor, so window resizes still need no pipeline
recreation; `recreate()` rebuilds the HDR target at the new extent.

## Acceptance
`POSTFX=1` looks **identical** to `POSTFX=0`. The startup log now reads
`scene -> offscreen HDR (R16G16B16A16_SFLOAT) -> present -> swapchain (...)`.
Watch for: a black/garbled scene (pipeline-vs-offscreen incompatibility), or
Vulkan validation errors mentioning the chunk/entity pipeline against the
offscreen render pass — both would be isolated to this brick (flip the flag off
to fall back).
