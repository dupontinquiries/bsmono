# v0.24.92 — validation test harness

**Opt-in brick.** Apply with `toolkit/apply_from_zip_v2.sh`. **Tooling only** —
adds `toolkit/harness/`, no engine code, no `.spv`, no shader changes. Applies
cleanly on any current tree (it only adds new files).

## Why

The whole problem this session: the assistant has no compiler in its sandbox, so
it ships shader/engine changes blind and you discover breakage (the v0.24.90
winding fix is the cautionary tale). This harness closes that loop. It has two
layers over one ruleset, with two consumers:

- **You** have the real toolchain (`cargo`, `glslc`/`glslangValidator` via the
  build, a GPU). You run the full harness to validate.
- **The assistant** has only Python + bash. It runs the static layer before
  shipping, so structural/contract/footgun errors are caught here, not on your
  machine.

## What's in it

`toolkit/harness/`:

- **`validate.py`** — pure-Python static validator (no compiler needed). Checks:
  GLSL delimiter balance, duplicate `(set,binding)` descriptors, push-constant
  size, the `chunk.frag` binding + face-UV contract (mirrors
  `world/shader_contract.rs`), the **v0.24.90 winding footgun** (re-added
  `flip_winding`, or the greedy normals test flipped to `dot>0` → hard ERROR),
  and accidentally-staged `.spv`. Exit 1 on any ERROR. With `--real` it also
  shells out to `glslc`/`glslangValidator` for an actual GLSL→SPIR-V compile.
- **`run.sh`** — orchestrator. Static layer + real GLSL compile (if the tools
  are installed) + the authoritative `cargo` suite (`shaders_compile`,
  `mesh_parity`, `octree_parity`, the engine winding/contract tests, and the SSR
  cpu-reference tests once they land).
- **`RULESET.md`** — the invariants both layers enforce, written down:
  §winding (the inward-on-purpose CPU mesher), §bindings, §spv, §froxel (live),
  and §ssr — the incremental SSR pass contract we'll build against.
- **`README.md`** — the iterate loop.

## Run it

```
bash toolkit/harness/run.sh            # full: static + real compile + cargo tests
bash toolkit/harness/run.sh --quick    # static + real compile only (skip cargo)
python3 toolkit/harness/validate.py    # static only
```

Non-zero exit = something failed; the output names the rule that fired. Good as
a pre-push hook or CI step.

## Next: SSR through this harness

Now that you can validate and iterate, SSR proceeds in the increments in
`RULESET.md` §ssr, each gated through `run.sh`:

1. **Offscreen foundation** — scene → offscreen HDR color (`SAMPLED`) + depth
   made `SAMPLED`, a fullscreen present pass, tonemapping moved out of
   `chunk.frag`. Acceptance: **the scene looks identical**. This proves the
   plumbing with zero SSR math.
2. **Reconstruction** — view-space position + normal from depth, validated by a
   CPU-reference `cargo` test (`crates/vk-harness/tests/ssr_reconstruct.rs`,
   same pattern as `gpu_meshing_octree_cpu_ref`) — no GPU needed.
3. **Ray-march + composite** — screen-space march with a reflectivity mask
   (water = reflective), CPU-ref test for hit/miss + reflected-UV, fresnel blend.

Each increment ships as a brick; the assistant runs `validate.py` first, you run
`run.sh` (real compile + cargo + the new cpu-ref test) plus the in-game look.
The big win: the math in increments 2–3 is checkable in `cargo test` without a
frame, so we're no longer relying on "ship and see a black screen."
