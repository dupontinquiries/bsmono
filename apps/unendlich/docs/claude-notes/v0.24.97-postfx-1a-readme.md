# v0.24.97 — post-FX increment 1a, wired (UNENDLICH_POSTFX)

This is the **behavior-changing milestone** of the SSR/post-FX work, and the
first one to actually verify. It's gated: default off ⇒ the renderer is
byte-identical to before.

## What it does

With `UNENDLICH_POSTFX=1`, the scene renders into an offscreen color target and
a fullscreen present pass copies it to the swapchain. Increment 1a is a pure
**passthrough** — no HDR, no tonemap move, no reflections — so the only thing it
proves is that the offscreen → present → swapchain plumbing (and egui through it)
works. The offscreen target is swapchain(sRGB)-format and `chunk.frag` still
tonemaps into it, so the sRGB encode/decode round-trip is neutral and the image
must be identical.

Apply on top of v0.24.96 (you have the building blocks from v0.24.94–96).

## How to verify (one A/B)

1. `bash toolkit/harness/run.sh` — real-compiles the shaders and runs cargo.
   This is the **first gate**: it must build. (I wrote the Vulkan blind — no
   compiler in my sandbox — so if `cargo build` errors, paste me the errors and
   I'll fix; that's the iterate loop the harness exists for.)
2. Launch normally (no flag) — baseline.
3. Launch with `UNENDLICH_POSTFX=1` added to your run command.

**Acceptance: the two should look identical.** Same scene, same UI, same colors.
If `POSTFX=1` is black, garbled, or crashes, that's isolated to this wiring and
your normal play (flag off) is untouched — tell me what you see and we iterate.

## What's deliberately NOT here yet

No visible difference is expected — that's the point of 1a. The visible wins come
next, on top of this proven plumbing:

- **1b (HDR):** offscreen → `R16G16B16A16_SFLOAT`, `chunk.frag` outputs linear
  HDR (tonemap skipped via a flag), `present.frag` does the tonemap. Still
  identical, but now in linear HDR so effects can composite before tone mapping.
- **Bloom:** bright-pass + `ui_downsample`/`ui_blur` + additive composite in
  `present.frag`. First clearly-visible payoff.
- **SSR:** reconstruction + ray-march, each with a CPU-reference `cargo` test.

## If it doesn't build

Most likely spots (blind-written ash): exact builder method names, a borrow in
the `world_renderer` render loop, or a `VulkanContext`/`Swapchain` field name.
All were modeled on `depth.rs` / `chunk_pipeline.rs` / `swapchain.rs`, so any
fix should be a one-liner. Send the `cargo build` output and I'll turn it around.
