# v0.24.111 — enable VK_KHR_portability_subset features (MoltenVK shadow sampler)

Second MoltenVK fix, paired with v0.24.110. Your run log showed, alongside the
draw-count flood, this repeated error:

```
VUID-VkDescriptorImageInfo-mutableComparisonSamplers-04450
vkUpdateDescriptorSets(): (portability error): sampler comparison not available.
```

## Cause

v0.24.109 enabled the `VK_KHR_portability_subset` *extension* but never chained
`VkPhysicalDevicePortabilitySubsetFeaturesKHR` into device creation. Per the
portability rules, any feature not explicitly enabled there defaults to **false**
— including `mutableComparisonSamplers`. The chunk fragment shader's binding 1 is
a `sampler2DShadow` (a comparison sampler), so its descriptor write was rejected.
Your device *supports* the feature (vulkaninfo: `mutableComparisonSamplers = true`)
— it just wasn't switched on.

## Fix

`create_device` now (macOS only) queries the device's supported portability
feature set and chains it back into `VkDeviceCreateInfo`, enabling exactly what
the hardware offers and nothing more. Linux is untouched (the whole block is
`#[cfg(target_os = "macos")]`).

## Apply order

This brick contains **two** patches — apply both onto your v0.24.109 tree:

1. `0001` = v0.24.110 (CPU draw path when drawIndirectCount absent) — the one you
   hadn't applied yet; this is why terrain was invisible.
2. `0002` = v0.24.111 (this portability-features fix).

Then rebuild and run with the same loader env. Expected: `Indirect drawing
DISABLED: per-chunk draw loop (CPU cull).` in the log (not "ENABLED"), the
draw-count flood gone, the comparison-sampler errors gone, and **terrain
visible**.

## If the build fails

The v0.24.111 change is blind `#[cfg(macos)]` code (can't be sandbox-compiled).
The one thing to watch is the type name `vk::PhysicalDevicePortabilitySubsetFeaturesKHR`
in ash 0.37. If it doesn't compile, drop just that commit
(`git reset --hard HEAD^`) and rebuild with v0.24.110 alone — terrain should still
render; shadows may look wrong until the sampler fix lands.

## Remaining non-blocking validation noise (for later)

- `VUID-StandaloneSpirv-None-10684` (`%planes` Function-storage array, ArrayStride):
  a SPIR-V decoration glslang emits that spirv-val rejects — in a cull/view compute
  shader. Harmless while the CPU draw path is active (that shader isn't dispatched).
- `vkGetQueryPoolResults … query not reset`: GPU-timer query pool needs a reset
  before first use; MoltenVK is stricter. Instrumentation only.
- `vkQueueSubmit … pSignalSemaphores` swapchain semaphore reuse: latent sync issue
  (per-image semaphores would fix it). Not blocking; app runs.

We'll pick these off after terrain is confirmed.
