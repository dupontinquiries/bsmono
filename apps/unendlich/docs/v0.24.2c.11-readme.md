# v0.24.2c.11 — Launcher core (`unendlich-launcher run`)

The first launcher ship. Version-aware test execution: run any
`.unendtest` against any git ref of the engine, get a clean result
file back.

## What's new

### `unendlich-launcher` binary

```bash
unendlich-launcher run tests/specs/rd2_smoke.unendtest --version @HEAD
unendlich-launcher run tests/specs/rd8_smoke.unendtest --version @v0.24.2-c.7
unendlich-launcher run tests/specs/rd2_smoke.unendtest --version @abc1234
unendlich-launcher run tests/specs/rd2_smoke.unendtest --version @my-feature-branch
```

What it does:

1. Resolves `@<ref>` to a commit hash via `git rev-parse --verify`.
2. Checks `~/.unendlich/versions/<hash>/unendlich-world` for a cached binary.
3. On cache miss: `git clone --local` to `~/.unendlich/clones/<hash>/`, checks out the commit, runs `cargo build --release --bin unendlich-world --features render --features gpu --features hot-shaders`, copies the built binary into the cache.
4. Creates a per-run output dir at `~/.unendlich/runs/r-<uuid>/`.
5. Spawns the cached binary with `--test-spec <path>`, setting `UNENDLICH_RESULT_PATH` and `UNENDLICH_EVENTS_PATH` env vars to redirect outputs into the per-run dir. **The spec on disk is not modified.**
6. On exit: surfaces the result file path and exit status.

```text
unendlich-launcher: resolving version @v0.24.2-c.10...

┌─ Run complete ─────────────────────────────────
│ commit:     abc1234...
│ result:     /home/user/.unendlich/runs/r-9f3a.../result.unendresult.json
│ events:     /home/user/.unendlich/runs/r-9f3a.../events.jsonl
│ exit:       Some(0)
│ assertions: PASSED
└────────────────────────────────────────────────
```

Exit codes:
- `0` — all assertions passed.
- `1` — assertions failed (result file still written, contents valid).
- `2` — launcher couldn't set up or build.
- `3` — binary aborted before writing result.

### Why local clones, not git worktree

`git worktree` shares `.git/` with the main repo, which can produce cryptic errors like `fatal: 'main' is already checked out at...` requiring `git worktree prune` to fix. Local clones (`git clone --local`) are fully independent: a separate `.git/`, no worktree metadata in your main repo, cleanup is just `rm -rf <dir>`. They share the git object database via hard-links so they're fast and space-efficient.

### Driver awareness deferred to c.12

GPU driver updates (Mesa, Honeykrisp) shift perf numbers in ways that have nothing to do with code changes. The c.11 result files don't yet record driver identity, so cross-version perf comparisons remain manually-discipline-bound for now. c.12 will:

- Add `gpu_driver_id` to result files (vendor/device IDs + driver version string).
- Add `unendlich-launcher compare` with driver-epoch filtering.
- Add `unendlich-launcher run-suite` for the "test-all button," scoped to current driver epoch.

The architectural premise — cross-version compare is most meaningful within a single driver epoch — is captured in DESIGN_NOTES so we don't lose the rationale.

- Shared `CARGO_TARGET_DIR` for fast incremental rebuilds (the first build per commit is slow, subsequent runs of same commit are instant from cache — that's the important case).

## Path layout

```
~/.unendlich/
  clones/                          # local clones (one per commit)
    abc1234.../
      .git/
      src/, Cargo.toml, ...        # checked-out source
      target/                      # cargo build artifacts
  versions/                        # cached binaries (the things that matter)
    abc1234.../
      unendlich-world              # copied from clone's target/release/
  runs/                            # per-invocation output
    r-9f3a2b1c0e4d5678/
      result.unendresult.json
      events.jsonl
```

Override `~/.unendlich/` location via `UNENDLICH_LAUNCHER_HOME` (useful for tests).

`versions/` is the important persistent state. `clones/` and `runs/` are scratch and can be deleted at any time. `runs/` accumulates; manual cleanup (`rm -rf ~/.unendlich/runs/*`) is fine. `clones/` accumulates more slowly (one per built commit); same recovery.

## Validation workflow

Pick a small spec (rd2_smoke is the cheapest) and run it via the launcher against the current HEAD:

```bash
$ cargo build --release --bin unendlich-launcher
$ ./target/release/unendlich-launcher run tests/specs/rd2_smoke.unendtest --version @HEAD
unendlich-launcher: resolving version @HEAD...
[cargo build output for ~60-90s on first invocation]
[unendlich-world startup logs]
[5s of normal run output]
[shutdown sequence]

┌─ Run complete ─────────────────────────────────
│ commit:     <40-char hash>
│ result:     /home/.../runs/r-.../result.unendresult.json
│ events:     /home/.../runs/r-.../events.jsonl
│ exit:       Some(0)
│ assertions: PASSED
└────────────────────────────────────────────────
```

Compare the result file against `tests/specs/rd2_smoke.unendresult.json` (from a direct `cargo run`): they should be nearly identical (same metrics, different run_uuid, different timestamps). If they are, the launcher is working end-to-end.

Then try an older version to test the build-and-cache path:

```bash
$ ./target/release/unendlich-launcher run tests/specs/rd2_smoke.unendtest --version @v0.24.2-c.7
# This will trigger a fresh clone + cargo build (slow first time, ~90s).
# Second invocation of same version is instant.
```
