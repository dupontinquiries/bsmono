# v0.24.NEXT+5 — weather: rain & lightning (atmospheric)

## What

A weather state model + renderer-side atmosphere modulation. Rain and
lightning, derived from the climate fields + time, applied to uniforms
the shader already consumes — no new draw passes, no shaders.

- `world/weather.rs` — pure, tested state model. `sample(time,
  humidity, temperature) -> WeatherState { precipitation, lightning_flash }`.
  Rain = humidity-gated storm noise over time; lightning = stochastic
  decaying flashes during heavy rain. Deterministic (frame-time seeded),
  so launcher replays reproduce identical weather.
- `world_renderer.rs` — before the UBO build, modulates a local copy of
  the atmosphere: rain darkens sky/sun/ambient and thickens fog;
  a lightning strike adds a bright flash to ambient + sky. The
  background clear color tracks the modulated sky so the horizon
  darkens/flashes too. Off unless `UNENDLICH_WEATHER=1`.

## What you'll see

- **Rain:** sky and lighting darken, fog thickens, the world goes
  overcast as a storm builds, then clears. Tied to humidity — humid
  regions storm, dry regions stay clear.
- **Lightning:** brief full-scene flashes during heavy rain (ambient +
  sky spike toward white, then decay over ~8 time units).

## What you won't see yet (honest limits)

This is the *atmospheric* layer only — the part that rides existing
uniforms. These need render work (a draw pass / shader / particle
system) and read this same state when they land:

- **Rain particles / streaks** — needs a particle draw pass.
- **Lightning bolt geometry + thunder** — needs line geometry + audio.
- **Surface wetness** (darken/glisten wet ground) — shader-side.
- **Rain → snow** below freezing — `temperature` is plumbed into
  `sample` but unused; the phase split is a state-side follow-up that
  pairs with the seasons snow-line item.

All tracked in `docs/CLIMATE_PATH.md`.

## Why it's low-risk

- **Flag-gated, default off.** `UNENDLICH_WEATHER` unset → `atmos_eff`
  equals the unmodulated atmosphere and the clear color is the original
  `self.clear_color`; the frame is byte-identical to pre-weather.
- **Pure, tested core.** 7 unit tests (bounded precip, no-rain-when-dry,
  rain-occurs-when-humid, no-lightning-without-heavy-rain, bounded flash,
  strikes-during-downpour, determinism). No GPU/shader dependency.
- **Render change is a local copy.** The bin's atmosphere computation is
  untouched; we modulate a `*atmos` copy used only for this frame's UBO
  and clear color.
- **Deterministic.** Uses `monotonic_frame` as the time base, so
  launcher captures are reproducible.

## How to verify

```bash
./scripts/sanity.sh    # expect 36 passed / 0 failed
```

Then playtest with weather on. Storms evolve over a few minutes at
default cadence; humid areas are where it rains:

```bash
... <your playtest flag mix> ... \
UNENDLICH_WEATHER=1 \
  cargo run --release --bin unendlich-world --features render,gpu
```

Stand in a humid region and watch the sky darken and flash as a storm
rolls through; dry regions stay clear. A/B by toggling
`UNENDLICH_WEATHER`. Pairs naturally with `UNENDLICH_SEASONS=1` (winter
storms read colder via the seasonal tint).

To make storms come faster while testing, the storm cadence is a const
(`STORM_PERIOD`) in `weather.rs` — lower it and rebuild if you want
rapid cycling for a visual check.

## Rollback

Flag-gated: just don't set `UNENDLICH_WEATHER`. To remove entirely:

```bash
git checkout <prev-tag> -- crates/unendlich-engine/src/render/world_renderer.rs \
  crates/unendlich-engine/src/world/mod.rs
rm crates/unendlich-engine/src/world/weather.rs
```

See `docs/ROLLBACK.md`.
