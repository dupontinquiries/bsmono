# v0.24.NEXT+2 — GPU mesher decoration parity (grass / water / lava)

## What

The octree GPU mesher emits only solid block faces. The CPU mesher's
three post-passes — grass tufts (`decorate_chunk`), water surfaces
(`emit_water_surface`), lava surfaces (`emit_lava_surface`) — were
never run for GPU-routed chunks, so Near/Mid chunks lost grass, water,
and lava when `UNENDLICH_GPU_MESHER=2` was on. (Root cause documented
in BACKLOG.md, confirmed this session.)

This ship runs those three CPU passes on the GPU mesh result, in the
octree dispatcher, right after readback and before the result is sent.
Gated behind a new flag, **off by default**:

```
UNENDLICH_GPU_DECORATE=1
```

## Why it's low-risk

- **Flag-gated, default off.** With the flag unset, the GPU pipeline
  behaves exactly as it did in RC42.1. Nothing changes until you opt in.
- **Purely additive.** The passes only *append* vertices/indices to the
  GPU mesh; they never modify the solid faces the GPU produced. Worst
  case is misplaced decoration, never a corrupted base mesh.
- **Reuses tested code.** `decorate_chunk` / `emit_water_surface` /
  `emit_lava_surface` are the same functions the CPU mesher has shipped
  for many versions. This ship only changes their *visibility*
  (`pub(crate)`) and *call site*.
- **Coordinate-correct.** Both the GPU mesher and these passes emit
  world-space vertices offset by `coord.block_origin()` (verified
  against `gpu_meshing_octree_cpu_ref.rs` and `decorate_chunk`). No
  double-offset.
- **~Zero cost when off, cheap when on.** `decorate_chunk` iterates only
  `chunk.plant_indices`; a chunk with no plants adds nothing. The
  water/lava passes are the same cost the CPU mesher already paid.

## Mechanism

- `OctreeGpuMeshRequest` gains `chunk: Arc<Chunk>` (refcount-cheap) and
  `current_tick: Option<u64>` (Copy), populated by the worker from the
  `MeshRequest` it already holds.
- The dispatcher reads `UNENDLICH_GPU_DECORATE` once at startup. In the
  result-send loop, on **dispatch success** (including empty-but-valid
  meshes, so all-water ocean-surface chunks still get water tops), it
  appends the three passes to the mesh before `res_tx.send`.

## Known limitation (follow-up)

Decoration is currently lit with **neutral light** (`sky: None`). The
per-chunk `Sky` isn't threaded through yet because `sky.rs` wasn't in
scope to confirm `Sky: Clone`. Tufts will appear but won't pick up
day/night sun shading until that's wired. One-line follow-up once
`Sky`'s derives are confirmed (add a `sky` field to
`OctreeGpuMeshRequest`, pass `Some(&r.sky)`).

Per-face block color (grass-top-green / dirt-sides) is **not** addressed
here — that's computed in `chunk_mesh_octree.comp` and needs the shader.
Tracked separately in BACKLOG.md.

LOD note: decoration runs for every GPU-meshed chunk (Near always; Mid
when `UNENDLICH_GPU_MESHER_MID=1`). At Mid LOD the base mesh is
stride-decimated but `chunk.plant_indices` is full-res, so tuft density
won't match the coarser base. Evaluate in playtest; gating decoration to
Near-only is a one-line change if Mid looks wrong.

## How to verify

```bash
./scripts/sanity.sh    # expect 28 passed / 0 failed
```

Then playtest **with the flag added** to your mix:

```bash
UNENDLICH_RENDER_DISTANCE=6 UNENDLICH_LOD_BANDS=2,6,6 \
UNENDLICH_GPU_MESHER=2 UNENDLICH_GPU_MESHER_MID=1 \
UNENDLICH_ADAPTIVE_UPLOADS=1 UNENDLICH_SUBMIT_SKIP=1 \
UNENDLICH_SLACK_SCHEDULER=1 UNENDLICH_BIASED_SHELL_WALK=1 \
UNENDLICH_UPLOAD_PRIORITY=1 UNENDLICH_DEVICE_LOCAL_MESH=1 \
UNENDLICH_MULTI_SCALE_CAVES=1 \
UNENDLICH_GPU_DECORATE=1 \
  cargo run --release --bin unendlich-world --features render,gpu
```

Look for: grass tufts on Near/Mid grass surfaces; water surfaces on
oceans/lakes; lava pools underground. A/B by toggling
`UNENDLICH_GPU_DECORATE` 1↔0 — the difference should be exactly the
decoration geometry. Watch the dispatcher log line for the
`UNENDLICH_GPU_DECORATE=1 — ...enabled` confirmation on startup.

If grass appears but is mis-lit (too flat at night), that's the known
`sky: None` limitation, not a bug — flag it and I'll thread `Sky`.

## Rollback

```bash
# This ship is flag-gated, so the simplest rollback is: just don't set
# UNENDLICH_GPU_DECORATE. To remove the code entirely:
git checkout <prev-tag> -- \
  crates/unendlich-engine/src/render/meshing_pool.rs \
  crates/unendlich-engine/src/render/mesher.rs
```

See `docs/ROLLBACK.md` for the full recovery system.
