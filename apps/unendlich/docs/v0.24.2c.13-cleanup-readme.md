## 3. New: `commands/install_to_path.sh`

Run once to symlink `unendlich-launcher` and `unendlich-analyze`
into `~/.local/bin/`, so you can use them from anywhere without
the `cargo run --release -p ... --` prefix.

```bash
./commands/install_to_path.sh
```

The script:
- Builds release binaries (`cargo build --release -p ...`).
- Symlinks them into `~/.local/bin/` (overwriting any existing
  symlinks for idempotency).
- Verifies `~/.local/bin` is in PATH; prints reminder if not.

After running once:
```bash
unendlich-launcher run tests/specs/rd2_smoke.unendtest --version @HEAD
unendlich-analyze optimize ~/.unendlich/runs/r-.../result.unendresult.json
```
Both work from any directory.

Symlinks (not copies) so `cargo build --release` updates take
effect immediately without re-running the install script.

## Bonus: `docs/v0.24.2c.17-plan.md`

A detailed plan document for the c.17 multiview-CSM implementation
arc. Not a ship — a roadmap.

**Key findings from reading the existing shadow code:**

1. **The current engine renders ONLY cascade 0.** Despite the 4-layer
   shadow image and 4× per-cascade compute pipelines, the actual
   shadow render pass binds C0's view-proj and draws into layer 0
   only. Cascades 1-3 are infrastructure-complete but unused.

2. **The c.5/c.6 era already tried per-cascade-pass rendering** and
   hit a 2.8× regression on Honeykrisp (per-framebuffer overhead).
   The code's own comments flag multiview as the planned path
   forward.

3. **Infrastructure for multiview is 80% in place.** `view_params`
   buffer holds all 4 cascades' view-proj matrices, updated on the
   GPU each frame. The shadow vertex shader just needs to read
   `view_params[1 + gl_ViewIndex]` instead of a push constant.

4. **Per-cascade culling is the medium-term win.** With all 4
   cascades drawing in one multiview pass, we'd be 4×-fill-rating
   the existing geometry. The win comes from frustum-union culling
   (c.17-b) and per-cascade frustum tightening (c.17-c).

5. **Real perf win is in c.17-c**, not c.17-a. c.17-a is wiring and
   may slightly regress perf. c.17-c switches the main fragment
   shader to per-cascade sampling, enabling tighter frusta and a
   shadow_map size reduction (2048² → 1024² per cascade) that
   together target 2-4× speedup on rd=8.

**Ship plan from the doc:**

- **c.17-a** (visual parity): wire up multiview, all 4 cascades
  render, main frag still samples layer 0. Probably slight regression.
- **c.17-b** (frustum-union cull): cull against union of all 4
  cascade frusta. 10-30% recovery.
- **c.17-c** (per-cascade sampling): main frag uses cascade
  selection. Real win, target 2-4× shadow speedup.
- **c.17-d** (tuning, fallback drop): cascade count, shadow map
  size, frustum tightening, remove fallback env var.

Each ship measurable via `unendlich-launcher compare`. The doc
includes per-ship validation criteria, rollback conditions, and
a file-by-file change manifest.

The doc is a working document — c.17-a will probably reveal new
constraints not yet anticipated. The plan is a starting point, not
a contract.
