## Layout
- `crates/` — `unendlich-engine`, `unendlich-shared`, `unendlich-launcher`, `unendlich-analyze`, `unendlich-dash` (telemetry UI), `unendlich-ui` (shared egui kit)
- `assets/`, `commands/`, `docs/`, `scripts/`, `tests/` — as in your repo
- `toolkit/` — off-engine tooling (not part of the game crates):
  - `apply_from_zip_v2.sh` — apply a patch zip onto your repo (commits + tags)
  - `apply_and_test.sh` — brick-by-brick apply **with** `cargo test` gating
  - `git_sync.sh` — sync helper
  - `unendlich-dash/` — the egui telemetry dashboard
  - `unendlich-telemetry.html` — the web telemetry view

## Standing delivery workflow
Each drop = **this monorepo** (read/diff) + a **patch zip** (apply). To apply:

```sh
# from anywhere; repo defaults to ~/Code/unendlich-development/unendlich-game
toolkit/apply_from_zip_v2.sh  unendlich-bricks-patch.zip  [repo-dir]
```

It preflight-checks (clean tree, branch, base is an ancestor), runs
`git am --3way` for each patch, then tags each new commit from the zip's `TAGS`.
Verified in-sandbox: applying onto a clean `88b5542` reproduces a **byte-identical
content tree** (`8b54534…`) with 0 module-resolution gaps. Roll back with the
`git reset --hard` line it prints.

## Not build-verified
There's no Rust toolchain where these bricks were authored, so they're
module-complete and logic-simulated (the navfield/flow kernels were cross-checked
against BFS / path-follow in Python) but never `cargo build`'d. Run
`toolkit/apply_and_test.sh` or `cargo build`; reset to the last good `brick/*` tag
if a subsystem fails, and send me the compiler errors for the per-module fixes.
