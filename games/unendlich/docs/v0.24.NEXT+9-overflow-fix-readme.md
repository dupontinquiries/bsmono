# v0.24.NEXT+9 — GPU mesher overflow fix (the missing meshes)

## Root cause (confirmed by your diag)

The GPU octree mesher overflows its fixed per-chunk buffers on dense
chunks and emits an empty mesh → a **hole**. Your logs:

```
octree-gpu-mesh-dispatcher: chunk {...} failed: octree mesher overflow: v=42112, i=117924
```

Two things were wrong:

1. **`INDEX_CAPACITY` was 65_535 — set equal to `VERTEX_CAPACITY`.** But
   indexed meshing emits ~1.5–3× as many indices as vertices (here 42112
   verts → 117924 indices, 2.8×). So a chunk index-overflows *long* before
   it vertex-overflows. The vertex count (42112) fit fine; the index count
   (117924) blew past 65_535. Heavy-foliage chunks (leaves don't merge in
   greedy meshing) hit this constantly.
2. **On overflow the dispatcher emitted an empty mesh**, leaving a hole.

Your own A/B nailed it: the version-0.24.63 diag run used the **CPU**
mesher (`UNENDLICH_GPU_MESHER` default 0) and "looked much more filled —
no missing meshes," because the CPU greedy mesher has no fixed cap. This
is a pre-existing GPU-mesher bug (present in baseline, as you saw), not
from any feature ship.

## The fix (two complementary parts)

1. **Raise `INDEX_CAPACITY` 65_535 → 131_072** (always on). Covers the
   observed index counts with headroom. Indices are read back as `u32`,
   so there's no 16-bit ceiling, and the constant is used consistently
   for buffer alloc, slot offsets, and the shader's capacity uniform — so
   the bump propagates correctly. Cost at `MAX_BATCH_CHUNKS=64`: **+16.8
   MB** index buffer. Most dense chunks now mesh on the GPU normally
   (with the shader's climate tint).

2. **CPU-mesher fallback on overflow** (default on;
   `UNENDLICH_GPU_OVERFLOW_FALLBACK=0` to disable). Any chunk that *still*
   overflows the bigger buffer is re-meshed on the CPU greedy mesher,
   which has no fixed cap, instead of becoming a hole. The chunk is
   already threaded into the dispatcher (from the decorate ship), so it's
   a direct `mesh_chunk_greedy(&r.chunk, …)` call. The fallback mesh is
   complete (solid + grass/water/lava baked in), so the extra decoration
   pass is skipped for it.

Together: **no more holes**, regardless of chunk density.

## Likely secondary benefits

- **Apparent "LOD overlap" may reduce.** Some of the overlapping-terrain
  look is the near-LOD *hole* revealing the coarse far-LOD behind it. Fill
  the holes and that mostly resolves.
- **Stutter/submit churn may ease.** Overflowing chunks never produce a
  usable mesh, so they can keep getting re-requested; filling them should
  cut some of that churn.

## Limitations / what this does NOT fix

- **Magenta foliage.** That's a *color* bug on rendered chunks, separate
  from the holes. Almost certainly the GPU mesher's per-cell color path
  (shader `chunk_mesh_octree.comp`, not in scope) or the climate tint.
  CPU-fallback chunks render with correct base block colors (no tint), so
  dense tree chunks that fall back may lose the magenta — but GPU-meshed
  chunks keep it until the shader is fixed. **To confirm it's the GPU
  path, not the seasons tint:** run with `UNENDLICH_GPU_MESHER=0` (CPU) —
  if colors are correct there, it's the GPU color path. Also try
  `UNENDLICH_SEASONS=0` to rule out the seasonal tint.
- **Missing top faces** on rendered chunks: the GPU mesher's top-boundary
  neighbor sampling (a chunk's top blocks need to know the chunk above is
  air). Shader/neighbor-logic side, pre-existing.
- **LOD overlap** beyond the hole effect: LOD-band management, pre-existing.

These three are tracked in `docs/BACKLOG.md`; the first two need
`chunk_mesh_octree.comp`.

## Files changed

- `crates/unendlich-engine/src/render/gpu_meshing_octree.rs` —
  `INDEX_CAPACITY` 65_535 → 131_072.
- `crates/unendlich-engine/src/render/meshing_pool.rs` — CPU fallback on
  dispatch overflow (flag `UNENDLICH_GPU_OVERFLOW_FALLBACK`, default on);
  decoration gated to GPU meshes only (fallback already decorates).

No new tests: the overflow + readback path needs a GPU; `mesh_chunk_greedy`
(the fallback) is the same well-tested CPU mesher used everywhere.

## How to verify

```bash
cargo build --release --bin unendlich-world --features render,gpu
# (then launcher/analyze separately, or fix gpu_mesh_bench and use -p)
```

Run with the GPU mesher on. The `octree mesher overflow ... failed`
holes should be gone; you'll instead see (far fewer) lines like
`...overflowed GPU mesher (...); CPU-fallback meshing` for the densest
chunks, and those chunks render. A/B with `UNENDLICH_GPU_OVERFLOW_FALLBACK=0`
to see the holes return.

Watch for: dense foliage areas now solid (no see-through holes), and the
"missing meshes" your diag showed under the GPU mesher should match the
filled look of the CPU-mesher diag run.

## Rollback

`INDEX_CAPACITY` revert is one line. Fallback is flag-gated
(`UNENDLICH_GPU_OVERFLOW_FALLBACK=0`). Full menu in `docs/ROLLBACK.md`.
