# v0.24.34..36 — visual completeness triplet (shading polish)

## Tagline

Three small shader-only ships, all visual completeness fixes.
Bundled together because they're shader-only, low-risk, and
share a single SPV rebuild. Each is independently rollback-able
via shader-only edits.

## Status

Built autonomously. All compile in head; not yet run.
Stacked on RC2 (v0.24.33-climate-tint).

## What's in the bundle

### v0.24.34-position-tint
Adjacent blocks of the same type get subtly different shades.
Three-channel trig-noise hash per world-block-position. Mirrors
CPU mesher's `tint_for_position`. Variance per-block-type
(grass = 0.18, snow = 0.08, etc.).

Visible effect: a 32×32 patch of grass no longer reads as one
uniform color — it has subtle small-scale variation. The
"Lego look" recedes.

Cost: ~6 mul + 3 sin/cos pairs per emitted face vertex. Cheap.

### v0.24.35-face-light
Per-face brightness modulation. Side faces dimmer than top,
bottom faces darkest. Matches CPU mesher's `FACE_LIGHT` table
(top 1.0, bottom 0.55, east/west 0.80, north/south 0.65).

Visible effect: depth via face-direction shading. Blocks read
as 3D solids instead of flat-colored shapes. The fragment
shader still applies sun ndotl on top — this is the sky-dome
ambient term.

Bumpy top retains 1.0 multiplier (consistent with flat top).

### v0.24.36-bumpy-side-align
Side faces of weatherable blocks (grass, dirt, sand, gravel,
snow) now drop their top corners to match the bumpy top
surface. Eliminates the visible gap where flat side faces met
bumpy tops at chunk-edge corners.

Logic gated: only when the block has a bumpy top emitted
(weatherable AND top neighbor non-solid). Otherwise corners
stay un-bumped.

Cost: 4 bumpy_height calls per surface-weatherable block.
Negligible.

## Combined visual impact

Before this bundle, mode 2 produced:
- Uniform per-block-type colors (Lego look)
- All face directions equally bright (no depth)
- Visible gaps between bumpy tops and flat side faces

After:
- Per-block subtle color variation (within-chunk variation)
- Per-face directional shading (depth/solidity)
- Bumpy surfaces flow seamlessly from top to side faces

Combined with v0.24.33-climate-tint (per-chunk biome variation),
mode 2 should now look visually competitive with mode 0 for the
common-block cases.

## What's still deferred

Visual gaps remaining vs. mode 0:
- **Per-vertex AO** (Minecraft-style corner darkening). Filed
  as v0.24.37 candidate. Requires diagonal neighbor sampling
  which v0.24.30's `sample_or_neighbor` doesn't support yet
  (single-axis-OOB only).
- **Sky-aware face brightness** (CPU mesher path with Sky
  context). Requires per-frame sky uniform or a baked sky
  ambient buffer. Filed.
- **Slope shading**. CPU mesher dims faces on steep terrain.
  Requires sampling 2-3 neighbors per emit. Filed.
- **Edge weathering** (worldgen_weathering darkens corner edges).
  Requires worldgen_weathering port to GLSL. Filed.
- **Material response matrix**. Full CPU port is substantial;
  the simple climate + position + face_light triplet covers
  most of the visible variance.

## Per-ship rollback

All three are shader-only; no Rust code touched.

**Rollback v0.24.36 only:** delete the side_top_bumpy block in
shader main. Corners stay un-bumped.

**Rollback v0.24.35 only:** remove `* 0.80`, `* 0.55`, `* 0.65`
multipliers at the 4 side-face + 1 bottom-face + 2 north/south
emit sites.

**Rollback v0.24.34 only:** delete the `color = color *
tint_for_position(...)` line and the `world_block_pos` setup.
Optionally delete the `tint_for_position` function itself.

All rollbacks: rebuild SPV with glslangValidator and update
the .spv.hash.

## Risk assessment

- v0.24.34: low. Math identical to CPU port. Worst case: visual
  reads weakly different from mode 0.
- v0.24.35: low-medium. Possible double-application if the
  fragment shader is doing its own face-direction shading. Visual
  symptom would be over-dimmed side/bottom faces. Easy to revert.
- v0.24.36: low. Geometric adjustment only; doesn't affect color
  or face count. If bumpy_height returns NaN, corner.y becomes
  NaN — invisible artifact. Geometry from the bumpy top is the
  ground truth; if it works, this should too (uses same function).
