# v0.24.2c.13-instrumentation-followup — diag tooling, latest symlinks, bucket mode disabled

Followup to c.13-instrumentation. Three changes:

1. **`unendlich-launcher diag` subcommand.** One-paste run summary.
2. **`~/.unendlich/latest-*` symlinks.** Stable paths to the most recent run.
3. **Bucket mode disabled** pending fix for Honeykrisp DEVICE_LOST.

## What's new

### `unendlich-launcher diag`

```
unendlich-launcher diag                    # use ~/.unendlich/latest-*
unendlich-launcher diag r-fd091c8a996c30db # specific UUID
unendlich-launcher diag --log-lines 100    # default 60
```

### `~/.unendlich/latest-*` symlinks

The launcher now updates these after every run:

```
~/.unendlich/latest-result.unendresult.json       → most recent result
~/.unendlich/latest-engine.log                    → most recent log
~/.unendlich/latest-events.jsonl                  → most recent events (if kept)
~/.unendlich/latest-<spec_name>.unendresult.json  → most recent per-spec
```

The per-spec symlink survives `run-suite`. If you run rd2, rd8, dense
in sequence, all three remain accessible:

```
latest-result.unendresult.json -> runs/r-XXX/result.unendresult.json  (the last one, dense)
latest-rd2_smoke.unendresult.json -> runs/r-AAA/result.unendresult.json
latest-rd8_smoke.unendresult.json -> runs/r-BBB/result.unendresult.json
latest-dense_smoke.unendresult.json -> runs/r-CCC/result.unendresult.json
```

Symlinks are best-effort: failures (filesystem permissions, non-Unix
platform) log a warning but don't fail the run.

### Engine log capture

Engine stderr is now teed to `engine.log` in each run's directory.
The launcher uses `Stdio::piped()` for stderr and a tee thread that
writes each line to both the user's terminal (UX unchanged — you
still see live progress) and the per-run log file (archived).

This means **you no longer need to use `2>&1 | tail -80`** to capture
the engine log. Every run gets its log saved automatically:

```
~/.unendlich/runs/r-XXX/engine.log
```

`diag` picks this up automatically.

### Bucket mode disabled

The c.13-instrumentation `UNENDLICH_SHADOW_BUCKETS=N` feature triggered
`Vulkan error: ERROR_DEVICE_LOST` on Honeykrisp (Asahi Linux M2 Max,
Mesa 25.3.6, May 2026). Reproducible: every bucket-mode run died at
~2 seconds wall-clock with zero chunks loaded.

Suspected cause: writing multiple `cmd_write_timestamp` calls
back-to-back inside the shadow render pass with no intervening draw
commands on early frames. The Vulkan SPEC permits this, but Honeykrisp
appears to choke on the pattern (likely undertested code path in a
brand-new driver).

**c.13-instrumentation-followup behavior:** Setting
`UNENDLICH_SHADOW_BUCKETS=N` logs an ERROR-level message explaining
the feature is disabled, then continues without bucketing. Indirect
drawing remains active. Shadow timing reverts to the single
`gpu shadow` zone from `GpuTimer`.

The `shadow_bucket_timer.rs` module is kept in the tree for future
work; only the construction call in `world_renderer.rs` is bypassed.
DESIGN_NOTES has the investigation writeup and three candidate fixes
for whoever revisits this.

**Workaround for now:** if you want to know shape-of-shadow-cost data
before c.17 ships multiview-CSM, use external tools. RenderDoc can
capture a frame and break down draw-by-draw costs. The Vulkan layer
`VK_LAYER_KHRONOS_validation` with timing extensions is another path.

## What's NOT in this ship

- **Fix for bucket mode.** Filed as a followup. Three candidate
  approaches in DESIGN_NOTES; needs a focused ship of its own.
- **`diag` aggregation across runs.** Today `diag` is one-run. A
  future could add `diag --since 1h` for last-hour summary or
  `diag --compare r-AAA r-BBB` for direct head-to-head.
- **`diag --json`** for machine-readable output. The current text
  format is human-first; if a future tool needs to consume it,
  we'll add JSON output then.

## Files changed

### Launcher
- `crates/unendlich-launcher/src/lib.rs` — engine.log capture via
  tee thread, `update_latest_symlinks()`, `unendlich_root_dir()`
  helper, `engine_log_path` on RunOutcome.
- `crates/unendlich-launcher/src/bin/unendlich_launcher.rs` — `diag`
  subcommand, updated help, updated "Run complete" footer with
  symlink reminder.

### Engine
- `crates/unendlich-engine/src/render/world_renderer.rs` — bucket
  mode disabled with explicit ERROR log. The `shadow_bucket_timer`
  is never constructed; field stays `None`. The per-chunk shadow
  fallback path's bucket boundaries are guarded by `bucket_active`
  (always false now), so they don't execute.

### Docs
- `docs/DESIGN_NOTES.md` — c.13-instrumentation-followup section,
  shadow_buckets DEVICE_LOST writeup with three candidate fixes.

### Versions
- All four crates → `0.24.2-c.13-instrumentation-followup`.
