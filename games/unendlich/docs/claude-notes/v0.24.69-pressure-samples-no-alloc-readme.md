# v0.24.69-pressure-samples-no-alloc

## Tagline

Tiny tick_sim cleanup: drop the per-call Vec allocation in
`pressure_samples` by adding a non-allocating iterator variant.
Four hot loops in `plant_lifecycle` switched. Estimated ~3 ms/sec
saved out of tick_sim's 60-180 ms/sec budget. Single autonomous
"keep going" finding from a read-only investigation of the tick_sim
bottleneck.

## Status

Drafted in sandbox. Two files (`pressure_sampler.rs` +
`plant_lifecycle.rs`). Independent of all other RCs; can apply
in any order. Ship zip:
`unendlich-rc34-pressure-samples-no-alloc.zip`.

## What this ship does

### Before

```rust
// pressure_sampler.rs
pub fn pressure_samples(...) -> Vec<PressureSample> {
    let mut out = Vec::with_capacity(n);
    // ... fill loop ...
    out
}

// plant_lifecycle.rs (4 sites)
for s in pressure_samples(coord, tick, dim, 8) { ... }
```

Per RD=6 frame: ~7400 small Vec allocations / sec (8-PressureSample
× 4 call sites × 925 chunks × 2 ticks/sec).

### After

```rust
// pressure_sampler.rs
pub fn pressure_samples(...) -> Vec<PressureSample> {
    // Delegates to the iterator + collect. Tests use this path.
    pressure_samples_iter(...).collect()
}

pub fn pressure_samples_iter(...) -> impl Iterator<Item = PressureSample> {
    // ... lazy iterator, no allocation ...
}

// plant_lifecycle.rs (4 sites)
for s in pressure_samples_iter(coord, tick, dim, 8) { ... }
```

Zero allocations in the hot loop. Tests unchanged (use the
Vec-returning wrapper).

## Why an iterator works here

Every production call site is a `for s in ...` loop — single
linear consumption, no random access, no `.len()`. The Vec was
purely intermediate storage being immediately destructured. An
iterator captures the same generation logic with no heap
involvement.

## Why keep the Vec version

Tests in `pressure_sampler.rs` compare full sample sequences with
`assert_eq!(a, b)` on `Vec<PressureSample>`. Switching them to
iterators would force them to `.collect()` first — a lot of
test churn for zero benefit. Leaving the Vec API in place
(delegating to the iterator) keeps tests stable.

## Estimated impact

| Cost item | Before | After |
|---|---|---|
| Heap alloc/sec (RD=6) | ~7400 | 0 |
| Heap alloc cost @ 200 ns/pair | ~1.5 ms/sec | 0 |
| Cache traffic per call | Vec header + payload | Stack-resident |
| Total tick_sim impact | — | ~3 ms/sec saved |

Out of tick_sim's reported 60-180 ms/sec budget, that's ~2-5%.
Small, but free. Real value: the change documents which functions
are on the per-tick hot path, making future optimizations easier
to spot.

## Backwards compatibility

- `pressure_samples` (Vec) still exists; signature unchanged.
- New export: `pressure_samples_iter`.
- All 4 in-tree call sites updated.
- No external API changes.

## Tests

All existing `pressure_sampler` tests pass unchanged (they use
the Vec version which delegates to the iterator). Math is
provably identical between the two — same hash, same seed mixing,
same coordinate extraction.

## Risks

- **LLVM inlining**: the iterator chain
  `(0..n).map(closure)` should compile to a tight loop in
  release mode. Debug builds may be slower than the Vec version
  due to less aggressive inlining. Acceptable since debug is
  never the perf target.
- **Future divergence**: the two function bodies are functionally
  identical. If you edit one, edit the other. A comment in the
  iterator version flags this for maintainers.
- **Catch-up case**: at higher band-divisor (catch-up scenarios),
  `sample_ticks` can be >1, meaning the inner `pressure_samples_iter`
  call happens multiple times per chunk per tick. The win scales
  proportionally — more allocations avoided.

## Architectural significance

Minimal — this is a constant-factor cleanup, not a complexity
improvement. The real architectural answer to the tick_sim
bottleneck is the dirty-set work (Finding 2 in the bottleneck
memo) which drops Pass 2 from O(plants-in-chunk) to
O(plants-transitioning). RC34 is groundwork: it removes one
per-call-site overhead so the next optimizer doesn't trip over
the allocation noise.
