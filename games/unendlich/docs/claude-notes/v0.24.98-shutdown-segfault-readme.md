# v0.24.98 — fix shutdown segfault (renderer.destroy ordering)

## Symptom
`segmentation fault (core dumped)` on **every** exit, right after the log line
`Pre-exit: dropping mesh_pool (may join worker threads + GPU dispatcher)...`.
Reproduces with and without `UNENDLICH_POSTFX` — it is **not** related to the
post-FX work; it is a pre-existing teardown-ordering bug in the GPU-mesher path
(`UNENDLICH_GPU_MESHER=2`).

## Root cause
In `bin/unendlich_world.rs`, the shutdown sequence called
`renderer.destroy(&ctx)` *first*, which frees the shared **octree GPU buffer**
(`octree_pool`). At that point the octree GPU mesher's **dispatcher thread**
(inside `mesh_pool`) is still alive — it isn't joined until `drop(mesh_pool)`,
several lines later. The renderer even logged the hazard itself:

```
octree_pool has 1 extra Arc reference(s) at destroy time (mesher hasn't
dropped yet — expected). Destroying the buffer; any later access will be UB...
```

So between `renderer.destroy()` and `drop(mesh_pool)`, the dispatcher could
touch the freed buffer → use-after-free → segfault. The code comment in that
block already documented the *intended* order (drop `mesh_pool` and the
GPU-mesher Arcs before tearing down), but the actual call sat above it.

## Fix
Move the single `renderer.destroy(&ctx)` call to **after** the
`mesh_pool` + GPU-mesher Arc drops and **before** `drop(ctx)`. New order:

1. `drop(mesh_pool)` — joins the dispatcher thread (CPU). The octree buffer is
   still alive, so the join is safe.
2. `drop(_gpu_mesher_for_cleanup)` / `drop(_octree_gpu_mesher_for_cleanup)` —
   releases the mesher's `octree_pool` reference (no more extra Arcs).
3. `renderer.destroy(&ctx)` — begins with `device_wait_idle()` (world_renderer.rs
   line ~4104), which drains any in-flight dispatcher GPU work, *then* frees the
   octree/mesh buffers with zero outstanding references.
4. `drop(ctx)` — device + instance teardown.

This is a pure reordering of one statement plus comments; no behavior changes
while running. The `octree_pool has 1 extra Arc reference ... UB` warning also
disappears, because the mesher Arcs are gone before the buffer is destroyed.

## Verify
Build and run as usual, then quit (Esc → close window). Expected: a clean
shutdown ending in `Shutdown complete.` / `Pre-exit: calling std::process::exit(0)`
with **no** `segmentation fault`, and **no** `octree_pool has 1 extra Arc`
warning. Confirm with both `UNENDLICH_GPU_MESHER=2` and the default CPU mesher.

## Scope note
Touches only the shutdown tail of `main()` in `bin/unendlich_world.rs`. It is
independent of the post-FX/SSR track and of the parallel mobs/items/cave-gen
work; the brick applies with `git am --3way` so minor context drift around
`main()` auto-resolves.
