# v0.24.107 — SSR groundwork: sampleable depth buffer

First step of the SSR (screen-space reflections) arc. Pure groundwork: makes the
depth buffer readable as a texture so the upcoming ray-march has a depth source.
**No behavioral change** — nothing samples depth yet, so this is invisible at
runtime (no A/B). It just adds capability.

## What changed (`render/depth.rs`)

- Image usage now `DEPTH_STENCIL_ATTACHMENT | SAMPLED` (was attachment-only).
- `pick_depth_format` now requires the format to support `SAMPLED_IMAGE` as well
  as `DEPTH_STENCIL_ATTACHMENT`. `D32_SFLOAT` satisfies both everywhere, so the
  selected format is unchanged in practice.
- New `DepthBuffer.sampler`: a NEAREST + clamp-to-edge point sampler (depth
  reconstruction wants exact texel values, not interpolation across silhouettes).
  Unused until SSR samples `view`.

Adding a usage flag + a sampler does not affect the attachment path: the depth
view is still attached as the depth attachment exactly as before.

## Why this first

SSR needs three inputs: depth (ray-march target), normals, and a material mask
(which surfaces reflect + how strongly). Depth is the most fundamental and the
only one addable with zero risk to the running renderer, so it goes first.

## SSR roadmap (remaining)

1. ~~Sampleable depth~~ (this brick).
2. **G-buffer via MRT** — add a second color attachment to the scene pass
   carrying world/view normal + a material reflectance/roughness mask. This is
   the invasive step: the scene render pass gains an attachment, so the
   chunk/entity pipelines (built against that pass) and `chunk.frag`/`entity.frag`
   outputs change. Water writes its WAVE normal here (never the flat face
   normal); wet stone / metal / ore write their material reflectance — that's
   where general reflections come from.
3. **Half-res Hi-Z ray-march** — march reflection rays against the depth buffer
   at half-res with a hard step cap + roughness-jittered rays (so reflections
   churn instead of staying mirror-sharp), temporally reused.
4. **Composite** — Fresnel-weighted SSR added in `present.frag` at the SAME
   linear, pre-tonemap site as bloom, behind `UNENDLICH_SSR` (a sub-toggle of
   post-FX, like bloom).

## Note

This stacks on the still-unverified post-FX/bloom tower. Step 2 (MRT) is the
riskiest blind change in the project — it touches the scene render pass every
pipeline is built against — so it's the best moment to have confirmed the
post-FX path actually runs before going further.
