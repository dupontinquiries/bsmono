# v0.24.88 — missing top faces (bumpy-top winding) fix

**Brick:** `unendlich-v0.24.88-bumpy-top-winding.zip` (patch series, `git am --3way`)
**Files:** 2 (`shaders/chunk_mesh_octree.comp`, `render/gpu_meshing_octree_cpu_ref.rs`)
**Stacks on:** v0.24.87 magenta fix (touches different code; applies independently).
**Status:** code written + statically/numerically verified here; **not** compiled
(no cargo / glslang in the authoring sandbox). The patch applies cleanly via

This is the "missing top faces" item from `docs/BACKLOG.md`.

---

## TL;DR

The bumpy top face (the 4×4 displaced grid emitted on weatherable blocks —
grass, dirt, sand, gravel, snow — at Near LOD) was **wound the wrong way**. Its
triangles had a **downward** geometric normal, the opposite of every other face
(including the flat +Y face). The chunk pipeline runs `front_face = CLOCKWISE`
+ `cull_mode = BACK`, so those tops were **back-faces and got culled** — they
rendered as nothing.

Result, exactly as in the screenshot: solid terrain looks **topless / holey**
(you look down *into* blocks), and grass/fern decoration **floats**, because
that decoration is anchored to the block and renders fine even when the block's
top is gone. Distant terrain looked OK because Mid+ LOD uses flat greedy tops
(correctly wound), and stone looked OK because non-weatherable blocks use the
flat +Y path — only the **Near-LOD weatherable tops** (most of the surface
around you) were affected.

The code even had the bisect switch for this already: `UNENDLICH_NO_CULL=1`
(chunk_pipeline.rs) — "faces visible from the side but gone head-on." With the
fix, the tops are visible under **normal** culling.

---

## Root cause

`emit_bumpy_top_quad` wound each sub-quad as `v00→v10→v11 / v00→v11→v01`
(traversing +X then +Z), and a misleading comment claimed that was "CCW from
+Y." It isn't — that order has a **−Y** normal. The flat +Y face
(`emit_quad` with `c010,c011,c111,c110`) traverses **+Z then +X** → **+Y**
normal, and that's the orientation that's visible under this pipeline (the
`CLOCKWISE` front-face setting accounts for Vulkan's clip-space Y-flip).

Numerically (one sub-quad, unit grid step):

| face                  | triangle normal.y | result        |
|-----------------------|-------------------|---------------|
| flat +Y (correct)     | +1.0, +1.0        | up — visible  |
| bumpy **old** (buggy) | −0.0625, −0.0625  | down — culled |
| bumpy **new** (fixed) | +0.0625, +0.0625  | up — visible  |

The normal's sign here is independent of the bump displacement (the bump only
moves Y; the up/down test uses the X/Z grid), so it's purely a winding error.

---

## What changed

**1. `shaders/chunk_mesh_octree.comp` — `emit_bumpy_top_quad`** *(the fix)*
Reversed the sub-quad winding to `v00→v01→v11 / v00→v11→v10` (+Z then +X), so
the bumpy tops face up and match the flat +Y face. No vertex positions, counts,
or anything else change — only triangle index order.

**2. `render/gpu_meshing_octree_cpu_ref.rs`** *(keep the mirror honest + lock it)*
- Same winding fix in the reference's `emit_bumpy_top_quad` (this file is the
  CPU mirror of the GLSL; it had the identical bug).
- New test `bumpy_top_triangles_face_up`: asserts every emitted bumpy-top
  triangle has a +Y normal. GLSL can't be unit-tested directly, but since the
  reference mirrors it line-for-line, this guards the shader's intent. It fails
  on the old winding and passes on the new.

Mesh parity (`mesh_parity.rs`) compares vertex/index **counts and bounding
box**, not winding, so this change leaves it green; both meshers are fixed
identically regardless.

## Apply

Partial patch series — use the overlay/patch tool, **not**
`commands/update_from_claude_zip.sh` (that wipes the whole tree).

```bash
./toolkit/apply_from_zip_v2.sh unendlich-v0.24.88-bumpy-top-winding.zip /path/to/unendlich-game
```

The manifest `base` is my local snapshot sha (won't exist in your repo →
`WARNING: base not present locally — applying anyway`, expected). It touches
only the bumpy-top emitter, so it applies cleanly whether or not v0.24.87 is in
yet. Roll back with the printed `git reset --hard`.

## Verify

**Winding regression test (headless, no GPU — fastest):**
```bash
cargo test --release -p unendlich-engine --features mesh-ref --lib \
  bumpy_top_triangles_face_up
```

**Compile / validate the shader (build.rs runs glslang on the .comp):**
```bash
cargo build --release -p unendlich-engine --features render
```

**On-hardware (the actual symptom):**
```bash
UNENDLICH_GPU_MESHER=2 cargo run --release --bin unendlich-world \
  --features="render,gpu,window"
```
Stand on grass/dirt and look down/across: tops are now present, terrain reads as
a solid surface, and the grass/fern decoration sits on the ground instead of
floating. Before/after cross-check: previously `UNENDLICH_NO_CULL=1` made the
tops reappear; now they're there under **default** culling (and `NO_CULL=1`
looks the same for tops).
