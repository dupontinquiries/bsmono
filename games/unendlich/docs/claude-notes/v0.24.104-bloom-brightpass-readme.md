# v0.24.104 — bloom: bright-pass + composite (gated `UNENDLICH_BLOOM`)

First bloom increment. Adds a half-res HDR bright-pass and composites it
additively into the present pass, in linear space, before the tonemap. Gated by
`UNENDLICH_BLOOM`, which is a **sub-toggle of `UNENDLICH_POSTFX`** (bloom samples
the linear-HDR scene offscreen that post-FX produces, so it only builds when
post-FX is active).

This is deliberately split like the post-FX chain was: **this turn = bright-pass
+ plumbing + composite** (a mild, half-res, bilinearly-upsampled glow); **next
turn = the separable blur** that widens it into a soft bloom. Splitting proves
the novel plumbing (a fragment pass writing an HDR target that the present pass
samples, plus the present descriptor/push-constant change) before stacking the
blur on top.

## What it does

- New `shaders/bloom_prefilter.frag`: rendered with the existing fullscreen
  `present.vert` into a half-res `R16G16B16A16_SFLOAT` target. 4-tap bilinear box
  downsample of the scene (the `ui_downsample` trick) + a Karis/COD **soft-knee
  threshold** (push constants `threshold`, `knee`) so only bright energy (sun,
  bright sky, water glints — values > 1.0 in the linear scene) bleeds.
- `present.frag` gains binding 1 (`bloom_color`) and a `bloom_intensity` push
  constant, and composites `color += texture(bloom_color, uv).rgb * intensity`
  **before** `tonemap_grade` (the same linear, pre-tonemap site SSR will use).
- New `render/bloom.rs` (`Bloom`): owns the half-res target, a color-only bloom
  render pass, framebuffer, and a `PresentPipeline`-shaped bright-pass pipeline.
  Fragment-based, reusing the proven `OffscreenTarget` + sampling-render-pass +
  fullscreen-triangle pattern from post-FX 1a/1b — **no hand-rolled compute
  storage-image barriers.** The bloom pass' final layout is SHADER_READ_ONLY, so
  the present sampler reads the result directly.
- New `swapchain::create_bloom_render_pass`: color-only, `load=DONT_CARE`,
  `final=SHADER_READ_ONLY`, with both external dependencies (incoming WAR so a
  ping-pong target is safe across frames, outgoing RAW so the write is visible to
  the present sampler).
- `postfx.rs` owns `Option<Bloom>`; records the bright-pass before the present
  pass begins, and pushes the intensity into the present draw.

## Why bloom OFF is identical to 1c

With `UNENDLICH_POSTFX=1` and bloom OFF:
- present binding 1 is bound to the **scene image itself** (always a valid
  descriptor), and
- the `bloom_intensity` push constant is **0.0**, so `color += scene * 0.0` adds
  nothing, and
- no bloom render pass is recorded.

So the entire path collapses to the v0.24.103 present chain. `finite * 0 = 0`
(no NaN risk).

## A/B

Build with hot-shaders as usual.

1. `UNENDLICH_POSTFX=1` **without** `UNENDLICH_BLOOM` → must look **identical** to
   v0.24.103 (1c). If it differs, the no-op composite or the binding-1 wiring is
   wrong.
2. `UNENDLICH_POSTFX=1 UNENDLICH_BLOOM=1` → bright areas (sun, bright sky, water
   specular glints) gain a **mild glow**. It will look half-res-soft, not yet a
   wide Gaussian bloom — that's the next increment. If bright regions look
   *blocky* rather than softly brightened, the bilinear upsample on binding 1
   isn't happening (sampler should be LINEAR — it is, inherited from
   `OffscreenTarget`).
3. Tuning knobs (consts in `render/bloom.rs`): `BLOOM_THRESHOLD` (default 1.0),
   `BLOOM_KNEE` (0.5), `BLOOM_INTENSITY` (0.05). If the glow is too subtle, the
   scene's linear highlights may rarely exceed 1.0 — lower the threshold toward
   ~0.8; if it's too strong/everywhere, raise it.
4. Resize the window — bloom recreates at the new half extent; the present
   binding 1 is re-pointed. No validation errors expected.

## Shader registration note

`bloom_prefilter.frag` is **not** added to build.rs's explicit `SHADERS` list, on
purpose: `present.vert`/`present.frag` aren't in it either yet compile and run
(post-FX 1a shipped), so the dev shader-compile path globs the whole `shaders/`
directory. `bloom_prefilter.frag` (same dir, `.frag`) is covered the same way.
This also avoids a patch conflict against a possibly-divergent build.rs. If you
ever see a runtime panic `could not read shader 'bloom_prefilter.frag.spv'`,
ensure your shader-compile step covers the directory (same fix as for
`present.*`).

## Validator

`67 ok, 0 warn, 0 error` (up from 63: `bloom_prefilter.frag` delimiters + 1
binding + ~8-byte push; `present.frag` now 2 bindings + ~4-byte push).
