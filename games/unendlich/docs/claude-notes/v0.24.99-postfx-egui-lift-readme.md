# v0.24.99 — post-FX: lift egui into the present pass (UI-free scene buffer)

Gated behind `UNENDLICH_POSTFX` (default off ⇒ byte-identical to today). This is
the keystone before HDR / bloom / SSR: it makes the offscreen scene buffer
**UI-free** so post-processing only ever touches the world, never the HUD.

## Why
With post-FX active the scene renders into an offscreen target and `present.frag`
copies it to the swapchain (increment 1a). Until now egui was still recorded
*inside* that offscreen scene pass. That blocks every later step:

- Once `present.frag` tonemaps (1c), the UI in the scene buffer would be
  tonemapped too — wrong; a HUD is display-referred, not scene-referred.
- Once the buffer is HDR float (1b), egui's **semi-transparent** elements (e.g.
  the translucent debug panel) would alpha-blend in linear space instead of the
  sRGB space they were tuned for — visibly different.
- Bloom/SSR would pick up the UI.

## What changed (all POSTFX-gated)
- `postfx.rs`: `record_present` split into `begin_present_copy` (begin pass +
  fullscreen copy, no end) and `end_present` (end pass), plus a
  `present_render_pass()` accessor. The caller can now record egui between the
  copy and the end of the present pass.
- `world_renderer.rs`:
  - egui is built against the **present** render pass when post-FX is on (else
    the main pass, as before). Both are the same swapchain sRGB color format, so
    the UI looks identical; egui's depth-stencil state is simply ignored by a
    color-only pass.
  - In the render loop, egui is recorded in the scene pass **only when post-FX
    is off**. When on, the scene pass draws world + entities only, then the
    present pass does: copy scene → record egui → end. The UI therefore
    composites on the sRGB swapchain, on top of the copied scene, never
    tonemapped.

Chunk/entity pipelines are unchanged and still target the (swapchain-format)
offscreen pass, so no pipeline recreation here — that arrives with 1b when the
offscreen target goes HDR float.

## Acceptance
`POSTFX=1` must look **identical** to `POSTFX=0`, HUD included — same scene, same
overlay, same translucency. The only difference is internal: the UI is now drawn
one pass later. Watch the debug panel / hotbar specifically; if the panel
translucency or text looks even slightly off, that's the thing to flag.

## Verify
Run with and without `UNENDLICH_POSTFX=1` and compare. If `POSTFX=1` shows no UI,
a mis-blended panel, or validation errors about the egui pipeline vs the present
pass, it's isolated to this brick (gate it off and the old path is unaffected).
