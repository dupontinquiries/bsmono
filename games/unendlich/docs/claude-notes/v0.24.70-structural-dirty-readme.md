# v0.24.70-structural-dirty

## Tagline

Replaces `POI_REFRESH_INTERVAL_TICKS=10` (placeholder cadence) with
explicit dirty marking. Idle chunks never rebuild their POI cache.
~2 ms/sec saved on tick_sim at RD=6; bigger architecturally — first
"can I ask if this chunk is unchanged?" signal in the codebase.
Finding 3 from tick-sim-bottleneck memo, shipped. Stacks on RC34
(both touch plant_lifecycle.rs; RC35's is a strict superset).

## What changed

Three files. New `structural_dirty: bool` field on `Chunk`:

- **Set** by `Chunk::set()` on wood transitions (add, remove,
  oak↔birch swap). All three transition paths covered.
- **Cleared** when InstallPoi applies a fresh cache (real
  chunk_manager path AND test apply path).
- **Read** by `should_refresh_poi` — the only consumer for now.

## The seam was pre-named

The doc comment on `Chunk::poi_cache` from a prior RC already
called this field by name: "rebuild iff `chunk.structural_dirty`".
RC35 ships exactly that.

## Tests added (+5 net)

- 6 in chunk.rs (dirty starts true; set/remove/swap dirty; non-wood
  noop doesn't dirty; same-block-set doesn't dirty)
- -1 +2 in plant_lifecycle.rs (cadence test removed, replaced with
  no-rebuild and rebuild-after-edit tests)

## Architectural significance

Small now (2 ms/sec). Big enabler later:
- Uniform-chunk skip (compressed-chunk sub-stage 0) wants this
- Mesh-cache eviction policy wants this
- Save-game incremental snapshots want this
- Render LOD upgrade-without-remesh wants this

## Risks (documented in ship readme)

- Phase A only covers wood transitions. Future bulk-edit APIs
  must remember to set the flag.
- Tests assuming dirty starts true now have an explicit fixture
  step: set `structural_dirty = false` post-build to get the
  steady-state.
- `POI_REFRESH_INTERVAL_TICKS` const is now unused but kept for
  doc reference.
