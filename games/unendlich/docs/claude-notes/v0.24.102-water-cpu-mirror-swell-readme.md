# v0.24.102 — water waves: CPU mirror + parity tests + wind-driven swell

Two things, both building on v0.24.101:

## 1. CPU mirror of the wave field (`world/water_waves.rs`)
A dependency-free `f32` transcription of `shaders/water_waves.glsl` — the same
constants, per-octave phase offset, column-major rotation, squared-sine
waveform, and swell. This is the single source of truth the eventual
buoyancy / entity-collision / splash system will query so floating objects
agree with the rendered surface (RULESET §water now points at it).

Tests (run under `cargo test -p unendlich-engine --lib`, which the harness
already drives):
- `field_is_deterministic_and_bounded` — same inputs → same height; bounded crest.
- `normal_is_unit_and_up_facing` — the normal is unit-length and points up.
- `analytic_gradient_matches_finite_difference` — **validates the core
  optimization**: the normal comes from the analytic gradient (one evaluation),
  and it matches a finite difference of the height. If the gradient math were
  wrong the GPU normal would be wrong too; this catches it on the CPU.
- `physics_drives_amplitude` — near-freezing water is far calmer than warm;
  still air is calmer than a stiff breeze; wind sets the (normalized) direction.
- `swell_modulates_amplitude_across_space` — the swell crest region is choppier
  than the trough region.

GPU↔CPU agreement is within last-ULP `sin`/`cos`/`sqrt` differences (sub-micron
for height — irrelevant to buoyancy). I can't run the GLSL in the sandbox, so
the test locks the CPU side and the RULESET freezes the shared contract.

## 2. Wind-advected swell (both GLSL + CPU)
A slow, low-frequency amplitude modulation that drifts downwind, so the chop is
no longer spatially uniform — calm patches and choppy patches. It's folded into
the per-octave amplitude (so it scales how rippled each region is); its own
~210 m slope is intentionally NOT added to the surface normal, which should
track the local ripples, not the swell tilt. Knobs: `WW_SWELL_FREQ`,
`WW_SWELL_SPEED`, `WW_SWELL_MIN`.

## Risk / verification
`world/water_waves.rs` is pure math with no engine dependencies, so it's
low-risk blind Rust; I validated delimiter balance, module wiring, and the
harness static pass (62 ok). The Rust test correctness rests on review + your
`cargo test`. The GLSL change is shader-only and still gated by
`WATER_WAVE_NORMALS`. No pipeline / Vulkan changes.
