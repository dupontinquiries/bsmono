# v0.24.2c.9 — `.unendtest` spec format + automated result writer

c.9 lands the test-spec layer. You write a `.unendtest` TOML file, the
binary runs it, you get a `.unendresult.json` back. The result file is
what we exchange now instead of "did you see shadows?" prose.

## What's new

### `.unendtest` (TOML in)

A declarative spec for how to run the engine and what to expect.

```toml
spec_version = 1
name = "rd2_smoke"
description = "Tiny RD, short duration — verifies the basic loop."

[engine]
binary = "unendlich-world"
duration_ms = 5000

[env]
UNENDLICH_RENDER_DISTANCE = "2"
UNENDLICH_VSYNC = "1"
UNENDLICH_INDIRECT = "1"
UNENDLICH_LOD_FACTORS = "4,8,16,32"

[expect]
duration_completed = true            # shutdown reason == max_duration
rendering_max = { min = 1 }          # at least 1 chunk visible at any point
shadow_p50_ms = { max = 200 }        # shadow median under 200ms

[output]
# Optional. Defaults to <spec_stem>.unendresult.json next to the spec.
# result_path = "..."
# events_path = "..."
```

Field semantics:
- `spec_version` (required, integer): currently `1`. Future binaries reject `> 1` with a clear error.
- `name` (required, string): identifier for the test.
- `description` (optional): free text.
- `[engine]`: `binary` (default `unendlich-world`), `duration_ms` (optional cap).
- `[env]`: every key/value is applied as a process env var **before** anything else reads env. So `UNENDLICH_RENDER_DISTANCE = "8"` overrides the default.
- `[expect]`: assertion table. See below.
- `[output]`: optional `result_path` and `events_path` overrides.

### Assertion shapes

Three forms in TOML, depending on what you're asserting:

```toml
shadow_p50_ms = { max = 80 }        # range, max only
rendering_max = { min = 80 }        # range, min only
some_metric = { min = 10, max = 50 } # range, both
duration_completed = true            # boolean predicate
some_metric = 100                    # scalar = sugar for { max = 100 }
```

The metric name is looked up in the result's `stats` map in three ways, in order:
1. Flat: `stats[name]`.
2. Dotted: `stats[head][tail]` for `head.tail`.
3. Suffix sugar: `stats[head][p50]` for `head_p50`. Suffix set: `min`, `p50`, `p90`, `p99`, `max`, `mean`, `value`.

So `shadow_p50_ms` matches `stats.shadow.p50_ms` (the GPU timer's per-zone percentile object) without you having to write the dot. And `rendering_max` matches `stats.rendering.max` (the workload distribution). Special-cased: `duration_completed` checks `shutdown_reason == "max_duration"`.

### Running a spec

```bash
$ cargo run --release --bin unendlich-world --features render --features gpu --features hot-shaders \
    -- --test-spec tests/specs/rd2_smoke.unendtest
```

The binary:
1. Reads the spec.
2. Applies `[env]` overrides to the process environment.
3. Sets `UNENDLICH_MAX_DURATION_MS` from `engine.duration_ms`.
4. Routes events.jsonl to `output.events_path` (or the default sibling).
5. Runs the normal main loop until the duration is hit.
6. At shutdown: builds the stats map, evaluates assertions, writes the `.unendresult.json`.
7. Exits with:
   - `0` if all assertions passed.
   - `1` if any assertion failed.
   - `2` if the result file couldn't be serialised or written.

## Cross-version provenance

Every result file records `binary_version` and `run_uuid`. So you can run the same spec against c.7 and c.9, get two result files, and the launcher (c.10+) will diff them automatically.

`spec_version = 1` means future binaries can detect "this is an old spec" and accept it. Future spec_version-2 specs will be rejected by c.9 binaries with a clear `UnsupportedVersion` error — no silent ignored fields.

## Hybrid determinism (the design choice)

- **World state is tightly deterministic**: same seed + same camera path → same chunks → same blocks. (Camera path support is c.10 work; for now stationary spawn.)
- **Perf metrics are loosely deterministic**: assertions use ranges (`max = 80`, `min = 80`), not exact values. Inherent run-to-run variance is expected. The assertion DSL was designed around it.
