# v0.24.37 + v0.24.38 — Minecraft-style vertex AO

## Tagline

Per-vertex AO darkens corners at inside-corners. Closes the
biggest remaining visual depth gap between mode 2 (octree GPU
mesher) and mode 0 (CPU mesher). Includes bumpy-AO so bumpy
tops match flat-top AO gradient.

## Status

Built autonomously. Shader compiles in head; SPV regenerated.
Not yet built or run on hardware. Stacked on RC3
(v0.24.36-shading-polish).

## What this ship does

### v0.24.37 — flat-face AO

For every emitted face, compute 4 per-corner AO factors using the
classic Mojang AO algorithm:
- For each face vertex, sample the 3 cells in the air-side
  half-space that surround the corner (two edge-adjacent + one
  diagonal).
- AO level: 0 (both sides solid → fully-occluded corner) up to
  3 (no occluders). Map to factor `mix(0.55, 1.0, level/3)`.

Inside-corners get visibly darker. Outside-corners stay full
brightness. The result reads as 3D depth — you can clearly see
which surfaces are concave vs convex.

### v0.24.38 — bumpy-face AO

The bumpy top sub-grid (4×4 sub-quads, 25 sub-vertices) now
bilinearly interpolates the 4 corner AO factors. Each
sub-vertex's color = `color * ao(u, v)` where (u, v) is the
sub-vertex's position in [0, 1]². Smooth AO gradient across
the bumpy surface.

## Combined visual impact

Before: flat-colored faces, hard to tell concave from convex.
Blocks look "plasticky."

After: depth perception via corner darkening. Caves, alcoves,
and tight terrain features pop visually. Bumpy surfaces also
get the gradient. Mode 2 should now be visually competitive
with mode 0 in the AO dimension.

## emit_quad refactor

emit_quad now takes 4 vertex colors instead of one:
```glsl
void emit_quad(
    uint counter_base, uint vertex_base, uint index_base,
    vec3 p0, vec3 p1, vec3 p2, vec3 p3,
    vec3 c0, vec3 c1, vec3 c2, vec3 c3
);
```

Single-color callers can use the `emit_quad_uniform` wrapper
(currently unused but preserved for future call sites that
don't want AO).

## Performance impact

Per-face AO sampling: 12 cell samples (4 vertices × 3 samples).
Per surface block: 1–3 exposed faces typical → 12–36 extra
samples per surface block.

Estimated mesher cost: from ~30 µs/chunk (v0.24.36) to ~50
µs/chunk. Well within budget. GPU L1 cache should help with
sample reuse between adjacent vertices.

If this turns out too slow (e.g., dispatcher timing logs show
>100 µs/chunk consistently), the AO can be:
1. Gated by an env var to A/B compare
2. Quality-reduced (sample fewer cells, drop the `corner` term)
3. LOD-aware (skip AO for chunks farther than X)

All filed as follow-ups if needed.

## Multi-axis-OOB samples

`sample_or_neighbor` only handles single-axis OOB (one chunk
boundary at a time). AO samples like (32, 32, 5) cross two
boundaries; my `ao_solid` returns false for these. The visible
artifact: at chunk-corner inside-corners, AO might be one level
off from correct. Visible only at world-loaded-set boundaries.
Acceptable.

A future ship could extend `sample_or_neighbor` to chain through
two neighbors for diagonal lookups; filed.

## Failure modes

- **AO too dark**: AO_MIN = 0.55 might be too aggressive on some
  surfaces. Easy to tune up (e.g. 0.65 or 0.70) without other
  changes.
- **AO too bright at corners**: if the sample positions are off
  by one, AO won't kick in where expected. Visual check: look
  at inside-corners (e.g., where two stone walls meet). Corner
  vertices should be noticeably darker than mid-edge vertices.
- **Bumpy AO mismatched with side-face AO**: bilinear corners
  use ao4_face_py, side faces use ao4_face_px/nx/pz/nz. Where
  a bumpy face meets a side face at a corner, the AO factor
  should match (both sample the same diagonal cell). If you see
  a visible AO "step" at the bumpy-to-side seam, the sampling
  needs alignment.

## CPU reference unaffected

The CPU reference function `mesh_chunk_octree_cpu_reference_*`
doesn't compute colors — it just emits vertex positions and
indices. Vertex count unchanged. All existing unit tests pass
(they only assert on count and AABB, not on color).

If you want to add per-vertex color to the CPU reference for
unit-testing AO correctness, that's a future ship (filed).

## Rollback

All changes are shader-only.

**Rollback v0.24.38 only**: revert `emit_bumpy_top_quad` signature
(drop `ao_corners`), revert sub-vertex color computation to
uniform, revert the bumpy caller to pass only `color`.

**Rollback v0.24.37 AND v0.24.38**: revert emit_quad signature
back to single color. Delete `ao_solid`, `compute_ao`, and the
six `ao4_face_*` functions. Revert all 6 face emit call sites
to single-color form. Revert bumpy as in v0.24.38 rollback.

After either rollback: rebuild SPV with glslangValidator and
update the `.spv.hash`.
