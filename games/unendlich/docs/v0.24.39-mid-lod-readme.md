# v0.24.39-mid-lod

## Tagline

GPU mesher now handles Mid LOD (16³ cells, 2-unit faces). Shader
parameterized via push constants; dispatcher batches by LOD;
worker routes Mid through GPU when env var enabled.

## Status

Built autonomously. Shader compiles in head. Rust changes touch
gpu_meshing_octree.rs and meshing_pool.rs. Not yet built with
cargo or run on hardware. Stacked on RC4 (v0.24.38-vertex-ao /
"0.24.38-bumpy-asym" cargo label).

## What this ship does

Before: octree GPU mesher only handled Near LOD. Mid LOD fell
back to CPU mesher (`mesh_chunk_downsampled`). The bin's mesh
pool ran 4 CPU workers — most of which were busy with Mid LOD
work that's a strict subset of what GPU could do.

After: with `UNENDLICH_GPU_MESHER_MID=1`, Mid LOD chunks route
through the GPU mesher with cell count 16, stride 2. Each thread
handles a 2³ source-block group, samples the low-corner block as
representative, emits 2×2-sized faces.

## Activation

```bash
UNENDLICH_GPU_MESHER=2 \
UNENDLICH_GPU_MESHER_MID=1 \
  cargo run --release --bin unendlich-world --features render
```

Default off (Mid stays on CPU) so you can A/B compare.

## Architecture changes

### Shader push constants

```glsl
layout(push_constant) uniform PC {
    uint vertex_capacity;
    uint index_capacity;
    uint batch_count;
    uint lod_cell_count;   // NEW: 32 for Near, 16 for Mid
    uint lod_cell_stride;  // NEW: 1 for Near, 2 for Mid
    uint _pad;
} pc;
```

PushConstants size: 16 → 24 bytes. Rust struct matches.

### Shader cell iteration

```glsl
uint cc = pc.lod_cell_count;
uint stride = pc.lod_cell_stride;
uint cell_idx = gl_WorkGroupID.x * 64u + gl_LocalInvocationID.x;
if (cell_idx >= cc * cc * cc) return;

uint mid_y = cell_idx / (cc * cc);
// ... decode mid_x, mid_z ...
uint x = mid_x * stride;  // chunk-local source-block coord
uint y = mid_y * stride;
uint z = mid_z * stride;
```

### Workgroup dispatch

```rust
let lod_cell_count = 32 / lod_stride;
let cells_per_chunk = lod_cell_count * lod_cell_count * lod_cell_count;
let workgroups_x = (cells_per_chunk + WORKGROUP_SIZE - 1) / WORKGROUP_SIZE;
// Near: 512 workgroups. Mid: 64. Far: 8. VeryFar: 1.
```

### Face emission scaling

```glsl
float s = float(stride);
vec3 c000 = p;
vec3 c100 = p + vec3(s, 0, 0);
// ...
```

Mid faces are 2 world-units across instead of 1. Same vertex
count per face (4) but each face covers more area.

### Feature gating by stride

- **AO**: `stride == 1u ? ao4_face_*(...) : vec4(1.0)`. AO disabled
  at Mid/Far/VeryFar. Sample offsets don't generalize cleanly.
- **Bumpy top**: `stride == 1u && is_weatherable(...) && !is_solid_opaque(n_py)`. Bumpy disabled at non-Near.
- **Bumpy side alignment**: gated by same `side_top_bumpy` predicate.
- **Climate tint, position tint, face_light**: still work at all
  LODs.

### Dispatcher LOD-aware batching

The dispatcher previously batched any incoming request. Now:

```rust
let mut pending: Option<OctreeGpuMeshRequest> = None;

loop {
    let first = pending.take().or_else(|| rx.recv().ok())?;
    let batch_lod = first.lod;
    let batch_lod_stride = lod_stride_for(batch_lod);
    let mut batch = vec![first];

    while batch.len() < batch_target && elapsed < timeout {
        match rx.recv_timeout(remaining) {
            Ok(r) if r.lod == batch_lod => batch.push(r),
            Ok(r) => { pending = Some(r); break; }  // flush current
            Err(_) => break,
        }
    }
    // dispatch batch at batch_lod_stride
}
```

Different-LOD requests don't waste — they seed the next batch.

### Worker routing

```rust
let mid_via_gpu = std::env::var("UNENDLICH_GPU_MESHER_MID")
    .map(|v| v != "0" && !v.is_empty()).unwrap_or(false);
let route_to_gpu = match req.lod {
    LodLevel::Near => true,
    LodLevel::Mid  => mid_via_gpu,
    _              => false,
};
```

Far/VeryFar still route to CPU. Wiring those up requires
re-enabling AO for higher strides (or accepting flat-color at
distance), filed.

## Sampling fidelity

Mid uses low-corner sampling (one block per 2³ group). The CPU
`mesh_chunk_downsampled` uses majority voting (>½ rule), giving
slightly different silhouettes near terrain boundaries (one
extra block here, one missing there).

For most terrain at Mid viewing distance this difference is
invisible. Filed: majority-voting GPU Mid sampler. Approach: in
the shader, sample all 8 blocks of the 2³ group and apply the
same majority rule. Cost: 8x sample reads per Mid cell (still
8x fewer cells than Near, so net same cost).

## Performance expectations

- Mid LOD per-chunk dispatch: ~8x fewer cells than Near. Mesher
  cost: maybe ~1/4 of Near (cells × 32 fewer faces × emit cost,
  with AO disabled).
- CPU offload: each Mid chunk that goes to GPU is one less CPU
  mesher work item. With ~4× the chunk count at Mid distance
  vs Near, this could free significant CPU.

## What's still deferred

- **Far / VeryFar GPU coverage**: factor 4 and 8. Same shader,
  just need stride=4 and stride=8. Filed.
- **AO at non-Near LODs**: AO sample offsets need scaling.
  Filed.
- **Majority-voting Mid sampler**: better fidelity. Filed.
- **Multi-LOD batched dispatch**: would need specialization
  constants or multiple compute pipelines. Filed.
- **Per-LOD channels in dispatcher**: cleaner than the
  single-channel + flush-on-LOD-change. Could reduce small-batch
  flushes when LODs are interleaved.

## Failure modes

- **Mid LOD chunks render empty**: most likely cause is the
  cells_per_chunk math being off in Rust (push constants) vs
  shader. Verify in logs: shader hash matches, no SPV mismatch
  warnings.
- **Mid LOD double-renders**: both CPU and GPU produce a mesh
  for the same Mid chunk. Look for ChunkManager's `mesh_version_for`
  check; the GPU result's version should match.
- **Wrong block IDs at Mid**: low-corner sampling picks one
  specific block from each 2³ group. Visual artifact: thin
  surface features (1-block layers) may disappear or be too
  prominent. Compare with CPU's downsampled output to confirm.

## Rollback

Setting `UNENDLICH_GPU_MESHER_MID=0` (or unset) reverts Mid to
CPU. Code stays in place; pure behavior change.

To fully revert the ship:
- Remove `lod_cell_count`, `lod_cell_stride` from PushConstants
  (both Rust and GLSL).
- Revert the shader's cell iteration to hardcoded `32u`.
- Revert face emit corners to `vec3(1.0, 0, 0)` etc.
- Remove `lod_stride` parameter from mesh_chunks_* signatures.
- Revert dispatcher loop to single-channel-any-LOD batching.
- Remove the route_to_gpu / `UNENDLICH_GPU_MESHER_MID` branch in
  worker.
- Rebuild SPV.
