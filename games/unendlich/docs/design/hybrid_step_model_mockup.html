R1 · R2 · long-form design instrument — not engine code

What this is showing (and the honest caveat)

The hybrid uses R2 as a planner, not an oracle: it proposes waypoint target states (cheap, can even be a search), but the R1 fill between waypoints is the authoritative, deterministic part — seeded by hash(seed, region, tick, digest(state)) so it's bit-reproducible. The planner's proposal is committed to the seed lineage, so a replay re-fills the same staged plan rather than re-searching (that's the determinism fix for using R2 at all).

The genome/population panels are the argument for the hybrid: pure R1 draws one conditioned outcome for the whole span and loses the trajectory — selection+drift over many generations is path-dependent, so a single jump misses the intermediate selection pressure (watch its residual grow as you increase the span). The hybrid keeps enough intermediate resolution (one R1 fill per generation-ish waypoint) to track it, while still collapsing the convergent water/fog channels cheaply. Convergent intermediates that land in the same coarse bucket are merged in the graph — fewer distinct states to carry.

Caveat: this is a toy with invented dynamics to make the shape of the tradeoff legible — the real residual/accuracy numbers come only from the dual-path benchmark against the actual engine sim. It is a thinking tool for the step model, not a measurement.
