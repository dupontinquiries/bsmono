# v0.24.NEXT+6 — water field foundation (heightfield + settle)

## What

Steps 1–2 of the water roadmap (`docs/CLIMATE_PATH.md`): a per-column
water-depth heightfield and a volume-conserving flow/settle pass. Pure
state — no rendering, no worldgen coupling yet, so the build is
byte-identical until a later increment wires it in.

- `world/water_field.rs` — `WaterField { depth: Vec<f32> }`, one depth
  per `(x,z)` column (4 KB/chunk vs. 128 KB for a full 3D field).
  - `empty()`, `at`, `set`, `total_volume`.
  - `settle_step(ground, rate)` — one relaxation step. Each column sends
    water to lower-surface neighbors (surface = ground + depth), scaled
    so it never sends more than it holds. **Exactly volume-conserving**
    and **deterministic**; depth stays `>= 0`. Closed chunk boundaries.

## Why this shape

Water is a surface phenomenon for what step 1 targets (lakes, oceans,
filling depressions), so a 2D per-column heightfield is the right
lightweight model — standard "shallow water." It can't do overhangs or
waterfalls (those want a 3D cell field, a much later step), but it gets
"pour water on a slope, watch it find its level" with 4 KB/chunk and a
cheap O(area) step.

The settle scheme is Jacobi-style: compute all transfers against the
current state into a delta buffer, then apply — so it's order-independent
and deterministic (launcher-replay safe). Outflux is capped at the
column's depth, which is what guarantees both non-negativity and exact
conservation.

## Tests (6, all in the module)

`empty_field_is_dry`, `settle_conserves_volume_on_flat_ground`,
`water_spreads_from_a_spike_on_flat_ground`, `depth_stays_non_negative`
(on a slope, every step), `water_flows_downhill` (accumulates at the low
end), `settle_is_deterministic`.

## What's NOT here (next increments — see CLIMATE_PATH.md)

1. **Field-driven mesh (step 3).** Mesher reads `field.at(x,z)` for the
   water surface height (partial fills) instead of the block top. First
   visible payoff. Will be flag-gated `UNENDLICH_WATER_FIELD=1`.
2. **Seed from worldgen.** Populate the field from `BlockId::Water` at
   load so existing oceans/lakes feed it.
3. **Cross-chunk flow.** Edge-column flux exchange with neighbor chunks
   (today water settles within a chunk only).
4. **Erosion (step 4)**, then **evaporation/rain cycle (step 5)** — step
   5 connects water to the moisture field weather rides.

```bash

```

There's nothing to playtest yet — this is the state foundation. The
tests are the validation; visible water comes with step 3. Since nothing
is wired into worldgen or the mesher, this ship cannot change anything in
a playtest (the module is constructed by no one yet — it's a library
ready for step 3 to use).
