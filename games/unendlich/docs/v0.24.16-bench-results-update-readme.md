## Key findings from v0.24.15

**Parallel extract scales ~2×, not ~3-4× as I'd hypothesized.**

```
records sequential: 7,117 us → 4-worker parallel: 3,496 us (2.04×)
runs sequential:    9,791 us → 4-worker parallel: 4,514 us (2.17×)
```

CPU naive parallel mesher also scales ~2.15× from its sequential
version, so the ~2× ceiling appears to be thread-launch + cache
overhead for these short workloads, not specific to the extractor.

**Honest totals (extract + dispatch) with parallel extract:**

| Path | Total | vs CPU naive par | vs MeshingPool |
|---|---|---|---|
| v2 honest (par) | 8,378 us | 0.64× | 3.54× |
| **v3 honest (par)** | **6,543 us** | **0.82×** | **4.54×** |
| CPU naive parallel | 5,356 us | — | 5.55× |
| MeshingPool | 29,694 us | — | — |

GPU v3 with parallel extract still loses to CPU naive parallel by
1.22× but wins over the production MeshingPool by 4.54×.
