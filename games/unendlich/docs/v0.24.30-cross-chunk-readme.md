# v0.24.30-cross-chunk

## Tagline

Mesher samples across chunk boundaries instead of treating them as
open. Eliminates z-fighting and doubled normals at chunk seams.
Visible quality win.

## Status

Built autonomously between play-test cycles. Compiles in head;
shader compiles via glslangValidator. NOT built with cargo or run
on hardware. Layered on top of v0.24.29-shared-octree (which is
itself untested).

## What this ship does

The mesher's neighbor-cell sample at `(x±1, y, z)` used to return
air whenever the cell fell outside this chunk's `[0, 32)` cube
(open-boundary semantics). That caused every chunk boundary to
emit a face from each side — the +X face on chunk N AND the -X
face on chunk N+1 at the same world-plane position. Both faces
have opposite normals; they z-fight and produce visible doubled-
normals at every seam.

`v0.24.29-shared-octree` made all chunks' octrees visible to the
mesher's shader through the shared pool. This ship uses that:
the mesher now passes 6 neighbor pool-slot indices per chunk
into `ChunkMetaGpu`. The shader's new `sample_or_neighbor`
function jumps to the neighbor's octree when sampling crosses a
boundary; if the neighbor isn't in the pool (boundary of the
loaded world), it falls back to open-boundary.

## What changes

### `ChunkMetaGpu` (Rust + GLSL)

Adds six `u32` neighbor base fields in `[+X, -X, +Y, -Y, +Z, -Z]`
order. `u32::MAX` is the "not resident in pool" sentinel.

```rust
struct ChunkMetaGpu {
    octree_base: u32,
    vertex_base: u32,
    index_base: u32,
    counter_base: u32,
    chunk_origin_x: i32,
    chunk_origin_y: i32,
    chunk_origin_z: i32,
    _pad: u32,
    neighbor_octree_base_px: u32,    // NEW
    neighbor_octree_base_nx: u32,    // NEW
    neighbor_octree_base_py: u32,    // NEW
    neighbor_octree_base_ny: u32,    // NEW
    neighbor_octree_base_pz: u32,    // NEW
    neighbor_octree_base_nz: u32,    // NEW
    _pad2: u32, _pad3: u32,          // NEW (std430 padding)
}
```

64 B total. Stays well under the chunk_metas buffer budget
(64 slots × 64 B = 4 KB).

### Shader

New function `sample_or_neighbor(meta, x, y, z)` — checks if
(x,y,z) is in-bounds, falls through to the neighbor's octree
otherwise. The original `sample_or_air` is kept as a legacy
helper for any caller that doesn't have ChunkMeta in scope (none
in the production mesher).

The 6 neighbor sample sites in the main loop now use
`sample_or_neighbor(meta, ...)` instead of
`sample_or_air(meta.octree_base, ...)`.

### Dispatcher

While holding the pool lock, the mesher's dispatcher resolves each
chunk's 6 neighbor pool slots via `pool.slot(neighbor_coord)`. If
present, captures `base_node_index()`; otherwise `u32::MAX`. The
6 values get written into ChunkMetaGpu's new fields per chunk.

### CPU reference

`mesh_chunk_octree_cpu_reference_with_neighbors(coord, octree,
neighbors)` is the new entry point. The old `mesh_chunk_octree_cpu_reference(coord, octree)` is now a thin wrapper that passes
empty neighbors (matches open-boundary behavior — keeps existing
unit tests valid).

New `Neighbors<'a>` struct: six `Option<&OctreeArray>`. Drop in
None for "open boundary for that face."

## New unit tests

- `neighbor_lookup_eliminates_seam_face`: stone block at the +X
  edge of chunk A, stone block at the -X edge of chunk B.
  Open-boundary: each emits 6 faces. With +X neighbor: chunk A
  emits 5 faces. Asserts the difference.
- `neighbor_lookup_symmetric`: same setup, viewed from chunk B
  with chunk A as its -X neighbor. Should also emit 5 faces.
- `neighbor_lookup_air_neighbor_still_emits`: stone block at +Y
  edge of chunk A, +Y neighbor is all-air. Should still emit all
  6 faces (the +Y face IS exposed).
- `cross_chunk_grass_top_face_still_bumpy`: grass blocks across
  a seam — +X face occluded (no emission), +Y face still bumpy
  (4 flat side faces + 1 bumpy top = 41 verts).

## What's still deferred

- **Diagonal-neighbor cells.** If you ever need to sample
  `(x+1, y+1, z)` (two-axis-out), this code falls back to air.
  The current 6-face mesher doesn't need it. The shader's
  `sample_or_neighbor` makes this explicit.
- **Version tracking on pool slots** (v0.24.31 candidate). The
  mesher still uploads every chunk every dispatch even if the
  same `(coord, version)` is already resident. Wastes ~640 µs
  per batch.
- **Deferred-free for evictions during dispatch** (v0.24.32).
  Main thread waits on the mesher's lock when evicting; not yet
  a measured pain point but a latency floor under bursty eviction
  load.
- **Mesh-output equivalence test** (gated by env). The CPU
  reference + GPU output could be compared at runtime now that
  both support cross-chunk neighbors. Roughly 50 lines of glue
  to write `mesh_set_equal(a, b)` (canonicalize each quad as a
  sorted 4-tuple, sort the resulting list, compare). Filed.

## Expected first-build issues

Beyond what v0.24.29 already had:

- **ChunkMetaGpu size mismatch with GLSL.** I matched the layouts
  carefully (8 + 6 + 2 = 16 u32 = 64 B in both) but a packed-vs-
  std430 misalignment can sneak in. If the dispatch is firing but
  meshes look corrupted on certain boundaries, this is the first
  thing to check. Add `const _: [(); 64] = [(); sizeof::<ChunkMetaGpu>()]`
  is already there on the Rust side.
- **Bumpy edge agreement across chunks.** Bumpy heights at a
  chunk seam should still agree since bumpy_height is a pure
  function of world coords. Both sides compute the same value.
  Cross-chunk occlusion just means one side DOESN'T emit; the
  emitting side's verts still match world coords with the other
  side if both did emit. Not a new bug, just worth verifying
  visually.

## Visual expectations

Looking at any chunk boundary: should see continuous terrain with
no doubled normals, no z-fighting, no visible "grid lines." A
fully-solid interior region (e.g., deep underground) should emit
ZERO outer faces from interior chunks — only the chunks at the
edge of the loaded set emit the boundary surfaces.

If you can tell where chunk boundaries are from looking at the
world, this ship didn't work and we need to dig in.

## Rollback

The cross-chunk path is purely additive: setting all
`neighbor_octree_base_*` fields to `u32::MAX` makes the shader
fall back to open-boundary (same as v0.24.29). To revert just
this ship:
- Revert `ChunkMetaGpu` to its 8-u32 form.
- Revert the shader's `ChunkMeta` struct + `sample_or_neighbor`
  to `sample_or_air`.
- Revert the dispatcher's neighbor lookup loop.
