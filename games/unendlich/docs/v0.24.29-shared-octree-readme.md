# v0.24.29-shared-octree

## Tagline

`OctreeGpuMesher` now reads octree data from the renderer's shared
`OctreeBufferPool`. Eliminates 100 MB of redundant HOST_VISIBLE
buffer and brings the mesher's octree reads under the v0.24.26
probe's coverage.

## Built autonomously, not visually tested

This ship was implemented during an autonomous deep-work session
between v0.24.28-bumpy-foundation playtest checks. It compiles in
the staging-tree reading, but has NOT been built with `cargo` or
run on hardware. The architectural shape follows the design memo
(`docs/v0.24.29-v0.24.30-design-memo.md`) Option A. Expected
first-build friction is moderate — borrow-checker complaints on
the lock-scope, possibly a missing `mut` on some intermediary,
that class of thing.

## What this ship contains

### Architectural

`OctreeBufferPool` is wrapped in `Arc<Mutex<...>>` in
`WorldRenderer`. New `WorldRenderer::octree_pool_handle()` returns
a clone of that Arc.

`OctreeGpuMesher::new` now takes `(ctx, octree_pool: Arc<Mutex<...>>)`.
Its constructor:
- Captures the pool's `vk::Buffer` handle under a short lock.
- Binds that buffer into its descriptor set instead of an
  internal one.
- Drops the internal `octree_buffer`/`octree_memory`/`octree_ptr`
  fields entirely.

### Dispatch path

The previous flow:
1. Upload chunk octree bytes to mesher's internal buffer at
   `slot_idx * MAX_NODES_PER_CHUNK * OCTREE_NODE_BYTES`.
2. Write `ChunkMetaGpu { octree_base: slot_idx * MAX_NODES_PER_CHUNK, ... }`.
3. Dispatch + readback.

The new flow:
1. Lock the shared pool.
2. For each chunk in the batch, `pool.upload(coord, octree)` —
   the pool's span allocator finds/replaces a slot and returns
   the absolute `base_node_index()`.
3. Write `ChunkMetaGpu { octree_base: pool_slot.base_node_index(), ... }`.
4. Dispatch + readback (pool lock still held).
5. Unlock — main thread can now evict.

The shader is UNCHANGED. `octree_base` is a u32 absolute node
index either way; the `octree_sample` walker doesn't care whether
that index points into a 100 MB or 256 MB buffer.

### Drop discipline

`WorldRenderer::destroy()` is called BEFORE `drop(mesh_pool)` in
the bin. That means the mesher's Arc clones are still alive when
the pool is destroyed. This is safe because:
- The mesher's `Drop` only destroys ITS OWN per-batch buffers
  (chunk_metas, vertex, index, counter).
- The mesher's cached `octree_pool_buffer: vk::Buffer` handle
  becomes dangling but is never used post-destroy.
- The strong-count is logged at destroy time for diagnostics.

### Skipped post-mesh upload

When `UNENDLICH_GPU_MESHER=2`, the bin's existing
`renderer.upload_chunk_octree(...)` call (which was the
post-meshresult mirror to the pool) is skipped — the mesher
already uploaded during dispatch. Saves one allocator
churn per chunk.

## What's NOT covered

- **Version tracking on pool slots.** Currently the mesher
  re-uploads every chunk every dispatch, even if the same
  `(coord, version)` is already resident. Wastes ~10 µs × 64
  chunks/batch = ~640 µs per batch on redundant memcpys. Fixing
  needs the pool to track `(coord, version) -> slot` and
  short-circuit identical uploads. Filed as v0.24.30.
- **Deferred-free for evictions during dispatch.** Main thread
  evicts must currently wait on the mesher's lock. Acceptable
  contention at steady state but a real latency floor under
  bursty eviction load. Filed as v0.24.31.
- **Cross-chunk neighbor lookups.** Now trivial since the pool
  holds all chunks' octrees — the mesher's shader can sample
  out-of-chunk world coords directly. Filed as v0.24.32 and
  blocked on visual confirmation that the bumpy aesthetic
  reads well.

## Expected first-build issues

1. **Lock-scope borrow weirdness.** I wrapped the upload loop in
   a block `{ let mut pool = pool_guard; ... }` to force the
   guard to drop at the right time. There's a `let _ = &pool;`
   marker at the end that the borrow checker may or may not
   accept depending on NLL pickiness.
2. **`mut` discipline.** Several variables (`outputs`,
   `node_bases`) became mutable inside the new structure. If I
   missed one, `cargo` will say so plainly.
3. **`gpu_mesher_mode` scoping** in the bin — I'm using it at
   line ~1955 but it's declared at line 461. Should be in scope
   for the whole `main()`.

## How to revert if it falls apart

The shared-pool refactor is structurally separate from
v0.24.28-bumpy-foundation. To revert just this ship:
- Restore `OctreeGpuMesher` to its v0.24.28 shape (internal
  `octree_buffer`/`octree_memory`/`octree_ptr` fields, takes
  only `&VulkanContext` in constructor, uploads to internal
  buffer in `mesh_chunks_one_submission`).
- Restore `WorldRenderer::octree_pool` to `OctreeBufferPool`
  (not `Arc<Mutex<...>>`); revert the 8 access sites.
- Restore bin's `OctreeGpuMesher::new(&ctx)` and remove the
  `gpu_mesher_mode != 2` guard on the post-mesh octree upload.

v0.24.28's bumpy emission + CPU reference + output-sanity probe
all stay valid; they're orthogonal to where the mesher reads
octree data from.
