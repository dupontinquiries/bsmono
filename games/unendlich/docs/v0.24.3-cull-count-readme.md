# v0.24.3-cull-count — count shadow vs main cull chunks (Option B)

After shadow-size falsified fragment-cost as the chug mechanism
(4× area reduction = 5% time reduction), the next question is: why
is shadow expensive? Two candidates:

1. **Shadow draws more chunks than main.** Its sun-aligned ortho
   frustum captures chunks the camera doesn't see.
2. **Shadow has higher per-chunk fixed cost** (state changes, tile-
   binning per draw, vertex setup).

This ship counts both, on CPU, every frame, and emits an event when
the shadow:main ratio is interesting.

## What it adds

### CPU-side cull count instrumentation

After the GPU's main cull dispatch, the engine iterates `self.meshes`
and runs CPU-side AABB-vs-frustum tests against both the shadow
cascade frustum and the camera frustum. The counts should match the
GPU cull's atomic-counter outputs to within floating-point noise.

Event `cull_count` carries:
- `shadow_count`: chunks passing shadow cull.
- `main_count`: chunks passing main cull.
- `total_count`: chunks in the renderer's pool.
- `ratio`: `shadow_count / main_count`.

**Emission gate:** only emits when `ratio > 1.5` OR `shadow_count > 50`.
Steady-state non-spike frames don't pollute the log.

### `unendlich-analyze cull_count` subcommand

Distribution of shadow/main/total counts + worst 10 + verdict line:
- ratio > 2.0: shadow draws significantly more chunks than main →
  fix is shadow LOD or cull tightening.
- ratio 1.3-2.0: shadow draws somewhat more → per-chunk fixed cost
  matters too.
- ratio ≤ 1.3: chunk count is not the explanation → per-draw or
  vertex cost is the issue.

## What it doesn't do

- **No fix.** Diagnostic only.
- **No GPU readback.** CPU computes the counts independently using
  the same frustum math. Cheap (~1-2 ms per frame at rd=8 with ~150
  chunks).
- **No new buffers, descriptors, or sync.** Adds zero pipeline
  complexity.

## How to use

```bash
cd ~/Code/unendlich-development/unendlich-game

# Reset spec (your previous run may have left UNENDLICH_SHADOW_MAP_SIZE in it).
sed -i '/UNENDLICH_SHADOW_MAP_SIZE/d' tests/specs/chug_capture_rd8.unendtest

# Clean stragglers.
git checkout -- assets/shaders/ 2>/dev/null
rm -f events.jsonl

# Migrate.
./commands/update_from_claude_zip.sh unendlich-v0.24.3-cull-count.zip
git add -A
git commit -m "Update to v0.24.3-cull-count"
./commands/tag_current_version.sh

# Rebuild.
cargo build --release -p unendlich-launcher -p unendlich-analyze

# Single run: rd=8, default 2048² shadow. Fly aggressively.
cargo run --release -p unendlich-launcher -- \
    run tests/specs/chug_capture_rd8.unendtest --version @HEAD

cargo run --release -p unendlich-launcher -- diag
UNENDLICH_EVENTS_PATH=~/.unendlich/latest-events.jsonl \
    cargo run --release -p unendlich-analyze -- cull_count
UNENDLICH_EVENTS_PATH=~/.unendlich/latest-events.jsonl \
    cargo run --release -p unendlich-analyze -- gpu_spikes
```

Paste back the `cull_count` output. The verdict line at the end tells
us which way to push next.

## What we're looking for

| Mean ratio | Interpretation | Next ship |
|---|---|---|
| > 2.0 | Shadow culls 2-3× more chunks | Shadow LOD or shadow cull tightening |
| 1.3-2.0 | Shadow draws somewhat more | Mixed: shadow LOD + investigate per-draw cost |
| ≤ 1.3 | Same chunks, different cost | Investigate per-draw / pipeline state overhead |

The distribution at the worst frames also matters — if `shadow_count
> 50` consistently at chug frames, that's a lot of geometry to push
through tile-binning regardless of ratio.

## Honest concerns

- **CPU-iteration cost.** At rd=8 with ~150 chunks, the per-frame
  iteration adds 1-2 ms of CPU work. We're spending ~106 ms/frame
  total in steady state; an extra 2 ms is noise. But: this is
  permanent instrumentation overhead until removed. Should be deleted
  or gated on an env var before any production ship.
- **CPU frustum may differ slightly from GPU.** Both use 6-plane
  AABB-vs-frustum tests. Floating-point differences at the boundary
  could include/exclude 1-2 chunks per frame relative to GPU. Not
  enough to confuse the ratio question we're answering.
- **Only emits when ratio is interesting.** At rd=2 with ~16 chunks
  rendering, may emit nothing at all. That's by design — diagnostic
  is tuned for rd=8.
