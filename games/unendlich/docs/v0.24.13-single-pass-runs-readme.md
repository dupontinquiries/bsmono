# v0.24.13-single-pass-runs — extractor optimization + honest totals

Two-part ship: (A) optimize the run extractor; (C) document honest
totals in bench-results.md.

## The honest-totals story

v0.24.12 measured real extract times for the first time:

```
records:  7,131 us total (198 us/chunk)
runs:    18,460 us total (512 us/chunk)
```

That changed everything about the "GPU runs wins 17×" narrative.
The honest total cost of the GPU runs path is `extract + dispatch`:
20,009 us for 36 chunks. MeshingPool: 28,980 us.

**Real win is 1.45×, not 17×.** The 17× was GPU dispatch only,
hiding the CPU-side extraction. bench-results.md now records
honest totals alongside dispatch-only numbers.

Also flipped: v2 (records) had a 2.6× cheaper extractor, making
v2 honest total (~12ms) FASTER than v3 honest total (~20ms). v3's
compression didn't pay for its expensive extractor.

## The fix

Rewrote `extract_surface_runs` as single-pass. Walks the chunk once
in `(y, z, x)` order; per cell, decides all 6 face emissions inline.

Open-run state tracking:
- **4 U=X faces** (+Y, -Y, +Z, -Z): runs reset at start of each
  `(y, z)` row. Stored as 4 scalar `Option<(BlockId, i32)>`.
- **2 U=Y faces** (+X, -X): runs span y-iterations. Stored in
  `[CHUNK_SIZE; CHUNK_SIZE]` state matrices indexed by `(slice=x, V=z)`.

End-of-row code closes any U=X open runs. End-of-chunk code closes
any U=Y open runs in the state matrices.

The old 6-pass version is kept as `extract_surface_runs_six_pass`
(`#[doc(hidden)] pub`). Used as test oracle and bench reference.

## Equivalence verified

Four new tests:
- `runs_v2_matches_six_pass`: messy chunk (mixed types, edges,
  corners, boundary blocks). Both extractors produce identical
  sorted output.
- `runs_v2_empty_chunk`: both produce zero runs.
- `runs_v2_full_chunk`: fully-solid chunk produces 6 × 32 = 192
  runs (boundary faces only, each face has 32 length-32 runs).
- `runs_v2_single_block_at_31_31_31`: corner boundary case.

**Test counts: 600 engine + 70 shared + 28 launcher = 698 tests pass.**

## Predicted hardware effect

- Single-pass extract: ~6 ms total for 36 chunks (~3× faster than
  6-pass)
- Speedup over 6-pass: ~3×
- GPU runs path total: ~6 ms extract + 1.5 ms dispatch = ~7.5 ms
  (was 20 ms)
- vs MeshingPool: ~3.9× (was 1.45×)
- vs CPU naive parallel: ~0.87× (still loses slightly)

If predictions hold, **v3 honest total is now faster than v2 honest
total** (12 ms). Production wiring decision points at v3.

If predictions fall short (say only 1.5× faster), v3 honest total
~14 ms — still loses to v2. Production wiring would pick v2.

The new compression analysis section is what to look at. If 1-pass
is meaningfully faster than 6-pass (~2-3×), the optimization
worked. If they're similar, the compiler's already inlining most
of the 6-pass version's array indexing and the gain is structural
only (less redundant chunk reads).

## What this ship does NOT do

- No GPU kernel changes.
- No parallel extraction. Both single-pass and six-pass still run
  sequentially in the bench. Parallel extract is filed for a
  follow-up (the bigger win on top of single-pass).
- No production wiring (Layer A.3). Still gated on the honest-totals
  comparison — though if single-pass works, the case is much stronger.

## Honest concerns

1. **The 32×32 state matrices** for U=Y faces are zero-initialized
   on every call. That's ~8 KB of writes per chunk, ~256 KB across
   36 chunks. Probably a wash vs the chunk-reads reduction, but
   it's worth seeing in numbers.

2. **My equivalence tests don't cover one important case**: chunks
   produced by the actual world generator (which has noise + biomes).
   The "messy chunk" is hand-built and may not exercise all edge
   cases. The bench's run-count assertion catches gross differences
   at runtime; subtle differences would still slip through.

3. **The compiler's vectorization** on the new code is uncertain.
   The macro-generated handle_ux / handle_uy bodies are uniform
   shape but contain BlockId comparisons and conditional emits.
   Whether LLVM produces tight code is empirical.

4. **End-of-chunk closing** of U=Y runs walks the full 32×32 state
   matrices for each face. That's a ~2 KB iteration; cheap but
   measurable. Could be skipped if we tracked which slots are
   actually open.
