# v0.24.2c.8 — Run UUIDs + structured event log + analyze CLI

The instrumentation foundation for the launcher arc (c.8 → c.12). This ship gives every run a unique identifier and a structured machine-readable event log alongside the existing human-readable terminal log.

## What's new

### Run UUID

Every invocation of `unendlich-world` generates a random run UUID at startup, e.g. `r-9f3a2b1c0e4d5678`. The UUID:

- Prefixes every line of the terminal log (custom env_logger format).
- Is recorded in every structured event in `events.jsonl`.
- Is recorded in the `RunBlock` appended to `run_summaries.txt`.

So you can pick up any single piece of output and trace it back to the matching records in the other two.

### `events.jsonl`

A parallel structured log written alongside the human-readable terminal log. One JSON object per line. Schema:

```json
{"uuid":"r-...","ts_ms":0,"kind":"start","version":"0.24.2-c.8","binary":"unendlich-world","cmdline":"..."}
{"uuid":"r-...","ts_ms":3,"kind":"flag","name":"UNENDLICH_RENDER_DISTANCE","value":"8","source":"env"}
{"uuid":"r-...","ts_ms":1000,"kind":"frame_window","window_secs":1.0,"frames":7,"frame_p50_ms":142.0,...}
{"uuid":"r-...","ts_ms":30100,"kind":"shutdown","duration_secs":30.1,"reason":"max_duration"}
```

Each event has `uuid`, `ts_ms` (relative to run start), `kind` — the rest depends on the kind.

Kinds emitted in c.8:
- `start` — first event, records version + binary + cmdline.
- `flag` — one per registered runtime flag, records name + value + source (env vs default).
- `frame_window` — emitted at each per-second log cadence, rolls up frame-time percentiles + workload counters.
- `shutdown` — last event, records duration + shutdown reason (`max_duration` vs `window_close_or_esc`).

Adding new kinds is just calling `unendlich::util::events::record("kind", json!({...}))` from anywhere. No schema changes elsewhere needed.

File path defaults to `events.jsonl` in cwd. Override via `UNENDLICH_EVENTS_PATH`. Multiple runs append to the same file; the UUID separates them.

### `unendlich-analyze` binary

A small CLI for querying `events.jsonl`. c.8 scope: `list` and `summarize` commands. Richer queries (`compare`, `where filter=value`, etc.) deferred to the launcher (c.10/c.11) which needs most of that machinery anyway.

```bash
# List all runs in events.jsonl.
$ unendlich-analyze list
UUID                 VERSION            SECS   WIN  SHUTDOWN
r-9f3a2b1c0e4d5678   0.24.2-c.8         30.1    25  max_duration
r-aabbccddeeff0011   0.24.2-c.8         12.4    11  window_close_or_esc

# Print a digest of one run.
$ unendlich-analyze summarize r-9f3a2b1c0e4d5678
```

## Why this ship

The c.4-c.7 arc exposed a real iteration-speed problem. Each ship was a guess + a playtest + a debate about what the playtest meant, because the data we had was thin and run-to-run variance was high. The c.6 "shadow fix didn't work" reversal was the worst case — one outlier 30s run nearly made me ship a regression-of-the-fix.

The pattern across c.4, c.5, c.7: **better instrumentation gave us answers faster than guessing.** This ship doubles down — every future bisect can sit on machine-parseable data instead of grep-the-terminal-scrollback.

It's also the foundation for c.9 (`.unendtest` test specs), c.10/c.11 (launcher with git-ref version dispatch), and c.12 (cross-version comparison). Without the UUID + events.jsonl machinery the rest of the arc has nothing to chew on.

## What's NOT in c.8

- The `.unendtest` spec format and test runner — that's c.9.
- The launcher binary — that's c.10/c.11.
- Cross-version comparison — that's c.12.
- Richer analyze commands (`compare`, `where`, etc.) — deferred to launcher.
- Removing the `process::exit(0)` belt-and-suspenders — kept since we still want safety while the launcher arc lands.
