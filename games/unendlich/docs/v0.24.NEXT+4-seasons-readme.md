# v0.24.NEXT+4 — seasons foundation (temporal climate axis)

## What

Adds the missing temporal leg of the climate triangle: a year-cycle
seasonal modulation, applied as a render-only tint delta. First concrete
step on the weather/seasons/water path (see `docs/CLIMATE_PATH.md`).

- `world/season.rs` — pure, fully-tested season model: `year_phase`,
  `temperature_delta`, `humidity_delta`, `season_for_phase`, and the
  `render_climate_delta(tick)` convenience. Summer (phase 0.25) warmest,
  winter (0.75) coldest, continuous across the year boundary.
- Wired into the GPU mesher's per-chunk climate-tint sample
  (`meshing_pool.rs`) as an additive delta on top of the base climate,
  clamped to `[0,1]`. Off unless `UNENDLICH_SEASONS=1`.

Because the renderer's climate-tint already consumes per-chunk
temperature/humidity (v0.24.33), this gives seasonal color shifts —
greener springs, drier/golden summers, cool damp winters — with **zero
shader changes**.

## Why it's worldgen-safe (the key design decision)

`temperature()`/`humidity()` feed `sea_level` → `density` — i.e. terrain
shape. If seasons modulated those fields, the world would re-grow its
terrain every year. So the seasonal delta is applied at the tint
*consumption* point, never baked into the climate fields. Worldgen reads
the base fields and is byte-identical. Verified by tracing
`sea_level`'s call to `humidity`.

## Why it's low-risk

- **Flag-gated, default off.** `UNENDLICH_SEASONS` unset → the tint is
  byte-identical to pre-seasons. `seasons_enabled()` reads the env once
  (OnceLock), not per chunk.
- **Pure, tested core.** `season.rs` has 6 unit tests (phase wrapping,
  summer>winter, bounded deltas, humidity inverse, season landmarks,
  year-boundary continuity). No GPU/shader/sky dependency.
- **Additive + clamped.** The delta shifts tint within `[0,1]`; can't
  produce invalid climate values.

## Known scope limits (documented in CLIMATE_PATH.md)

- **GPU path only.** Near/Mid chunks (GPU-meshed) get the seasonal tint;
  Far-LOD (CPU-meshed via `sample_env_at`) doesn't yet — a subtle tint
  seam at the Mid/Far boundary. CPU-path parity is the next increment
  (needs tick threading through the emit helpers).
- **No live transition yet.** Newly-meshed chunks reflect the current
  season; static already-meshed chunks won't visibly change until
  re-meshed. A throttled periodic re-mesh trigger is the follow-up.
- **Global, no latitude.** Whole world shares one season phase;
  hemispheres/equator come later.

## How to verify

```bash
./scripts/sanity.sh    # expect 32 passed / 0 failed
```

Then playtest with seasons on and a short year so the cycle is
observable in a session:

```bash
... <your playtest flag mix> ... \
UNENDLICH_SEASONS=1 UNENDLICH_TICKS_PER_YEAR=20000 \
  cargo run --release --bin unendlich-world --features render,gpu
```

As you play (and chunks re-mesh on movement/edits), grass/foliage tint
should drift warmer-and-drier toward summer, cooler-and-damper toward
winter. A/B by toggling `UNENDLICH_SEASONS`. Default mix (flag unset) is
unchanged.

To eyeball a specific season fast, set a large tick offset isn't
possible from env yet — instead pick `UNENDLICH_TICKS_PER_YEAR` small
(e.g. 2000) and watch the cycle accelerate.

## Rollback

Flag-gated: just don't set `UNENDLICH_SEASONS`. To remove entirely:

```bash
git checkout <prev-tag> -- \
  crates/unendlich-engine/src/render/meshing_pool.rs \
  crates/unendlich-engine/src/world/mod.rs
rm crates/unendlich-engine/src/world/season.rs
```
