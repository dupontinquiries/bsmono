# v0.24.2c.2 — Persistent Run Summaries & Rich Performance Logging

This ship adds three things on top of the bisect work:

## 1. `run_summaries.txt` — every run gets a block

At shutdown, `unendlich-world` appends one block to `run_summaries.txt` in the cwd. Each block has explicit start/end markers, an ISO 8601 timestamp, version, duration, command-line, env-vars-in-effect, and the full GPU/CPU/mesher summaries.

Format:

```
==== RUN START 2026-05-11T05:38:32Z ====
version: 0.24.2-c.2
duration: 81.0s
cmdline: target/debug/unendlich-world
env:
  Flags in effect (binary=unendlich-world):
    UNENDLICH_RENDER_DISTANCE = 64
    UNENDLICH_LOD_FACTORS     = 4,8,16,32
    UNENDLICH_VSYNC           = 1
    UNENDLICH_INDIRECT        = 1
    UNENDLICH_SHADOW_CASCADES = 1
    UNENDLICH_SHADOW_LEGACY_FB = 1
---- summaries ----
GPU timer lifetime summary:
  cull        n=  1138  mean=   3.49ms±  5.32  p50=  3.20  p90=  4.10  p99= 28.50  min=  0.00  max= 121.11  over_5.0ms=86 (7.6%)
  ...
==== RUN END 2026-05-11T05:38:32Z ====
```

### Useful greps

- List all runs:
  ```bash
  grep "^==== RUN START" run_summaries.txt
  ```

- Extract the block for a specific run (by start timestamp):
  ```bash
  awk '/^==== RUN START 2026-05-11T05:38:32Z/,/^==== RUN END/' run_summaries.txt
  ```

- Compare two consecutive runs' GPU summaries:
  ```bash
  awk '/^==== RUN START/{n++} n==5,n==6{print}' run_summaries.txt | less
  ```

- Find runs with specific env vars:
  ```bash
  grep -B5 "UNENDLICH_SHADOW_CASCADES = 4" run_summaries.txt | grep "RUN START"
  ```

## 2. Rich per-zone summary

Replaces the prior `mean stddev min max` line with:

```
  shadow      n=  1138  mean=  64.85ms± 56.44  p50= 3.20  p90=38.40  p99=85.40  min= 0.00  max=265.05  over_8.3ms=421 (37.0%)
```

The new fields:
- **p50 / p90 / p99**: percentiles by linear interpolation. p99 catches the streaming tail that mean+stddev hide for bimodal distributions.
- **over_8.3ms**: count and percentage of frames exceeding the 120fps budget. Single number that communicates "how often does this zone stutter."

Per-zone budgets (used for the `over_*` column):
- `shadow`, `main`, `total`: 8.333ms (120fps full-frame target)
- `cull`, `froxel`: 5ms (should-be-cheap; >5ms is suspicious)
- `wait_fences`: 8.333ms (stutter rate proxy)
- `record`, `submit`, `present`: 1ms (small-overhead zones)
- `acquire`: no budget (high variance is normal — vsync waits land here)
- Mesher per-LOD: no budget (off the frame-budget critical path)

## 3. Box plots

Below the rich-format block, one ASCII box-and-whisker per zone:

```
  ── box plots ──────────────────────────────────────────────────
  cull             0.00ms |-[==X==]-----------------------------------------------|  121.11ms  (p25=0.20 p50=0.45 p75=2.80)
  shadow           0.00ms X----------------------------------------------------------|  265.05ms  (p25=3.00 p50=3.20 p75=3.40)
```

Legend:
- `|` = min/max endpoints
- `-` = whiskers (min..p25 and p75..max)
- `[==...==]` = IQR box (p25..p75)
- `X` = median (p50)
- `#` = collapsed box (when p25 == p75)
- `X.........` = collapsed range (when min == max — all samples equal)

Visually:
- A long thin tail to one side means streaming spikes (most frames cheap, some expensive).
- A fat box in the middle means consistently variable cost.
- A collapsed-range plot (`X.........`) means flat steady-state — common when vsync is dominating.

## How to use these together

Typical A/B workflow:

1. Run with config A:
   ```bash
   UNENDLICH_SHADOW_CASCADES=1 UNENDLICH_SHADOW_LEGACY_FB=1 \
     cargo run --release --features render --features gpu --features hot-shaders --bin unendlich-world
   ```

2. Run with config B:
   ```bash
   UNENDLICH_SHADOW_CASCADES=4 UNENDLICH_SHADOW_LEGACY_FB=0 \
     cargo run --release --features render --features gpu --features hot-shaders --bin unendlich-world
   ```

3. Diff the GPU shadow lines from the two runs:
   ```bash
   grep -A20 "^==== RUN START" run_summaries.txt | tail -50 | grep "shadow"
   ```

4. Compare the `over_8.3ms` fraction — that's the stutter-rate signal mean alone won't show.

## Implementation notes

- **Sample retention**: `ZoneStats` now keeps a `Vec<u32>` of microsecond samples for percentile computation. Memory cost: ~13.7 MB for a 1-hour run at 120fps across 8 zones. Acceptable.
- **Percentile method**: linear interpolation between nearest ranks (numpy/R default). For 1000 samples, p99 = interp(sorted[989], sorted[990]).
- **Atomic appends**: `RunBlock::append` opens the file with `O_APPEND` and writes the whole block in one `write_all` call. POSIX guarantees atomicity for small writes; the framing markers make recovery easy if a large block ever interleaves.
- **Timestamp format**: matches the existing log lines (`YYYY-MM-DDTHH:MM:SSZ`). Self-contained iso8601 formatter so we don't pull in chrono/time as a dep.
- **Failure mode**: if writing `run_summaries.txt` fails (read-only filesystem, disk full), the binary logs a warning but doesn't block shutdown. The terminal log still has the same content.
