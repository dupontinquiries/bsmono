# v0.24.28-bumpy-foundation

## Tagline

First Ship-B-class mesher: 4×4 bumpy top faces on weatherable blocks,
with the falsification gates v0.24.27's debugging arc said we should
have had from the start.

## What this ship contains

Layered on top of the consolidated v0.24.27-octree-mesher (which after
fix3 produced flat correct terrain in mode 2):

1. **CPU reference port** of the GPU octree mesher
   (`gpu_meshing_octree_cpu_ref.rs`). Bit-equivalent to the GLSL
   modulo float ordering. 14 unit tests covering:
   - Empty / fully-solid / single-block / two-adjacent / non-origin
     chunks for the flat mesher.
   - Output-invariant checker accepts/rejects: AABB violations,
     bad index range, non-multiple-of-4 vertex counts, NaN
     positions.
   - `bumpy_height` determinism + non-positive bound + adjacent-edge
     agreement.
   - Bumpy emission for a single grass block (5 flat + 1 bumpy
     face = 45 verts / 126 indices).
   - Bumpy world-coord regression: chunk at `(1, 2, -1)` must emit
     bumpy vertices in the correct world AABB. This is the
     specific test that would have caught v0.24.27-fix3 if it had
     existed before.

2. **Output-sanity probe in the dispatcher**, gated by
   `UNENDLICH_OCTREE_MESH_VERIFY=1`. Runs
   `check_mesh_invariants` on every produced mesh. Counts violations
   per 10-second window. Logs the first violation per window at
   WARN. The check is cheap enough to run in production.

3. **Throttled batch diagnostic.** The fix2 diagnostic was logging
   every batch (30+/sec at steady state) — too noisy to keep on.
   Now it accumulates and flushes once per 10 seconds. Includes
   `empty=`, `nonempty=`, `avg_verts=`, `max_verts=`,
   `invariant_violations=`.

4. **4×4 bumpy emission on weatherable top faces.**
   - Static classification (not yet instance-driven): Grass, Dirt,
     Sand, Gravel, Snow are weatherable. Stone / Bedrock / wood / etc.
     stay flat.
   - `bumpy_height(world_x, world_z)` is hash-based 2-octave
     noise, deterministic, always ≤ 0 (bumps dip down only — never
     up — to avoid step-seams at terrain breaks).
   - 5×5 vertex grid per weatherable top face = 25 verts and 16
     sub-quads (96 indices). Vs. flat: 4 verts and 6 indices.
     Inflation: 6.25× verts, 16× triangles, but ONLY on weatherable
     top faces — non-weatherable blocks and non-top faces emit
     normally.
   - Adjacent blocks agree at shared edges by construction (same
     world coords → same bumpy_height).

5. **Documentation**:
   - `DESIGN_NOTES.md` Increment 72 (full v0.24.27 arc with three
     sub-ship fixes and the substrate-vs-consumer pattern note).
   - `DESIGN_NOTES.md` Increment 73 (this ship).

## Falsification gates

This ship's testing discipline addresses the gap that v0.24.27
exposed: **a substrate probe verifies the substrate, not its
consumers**. Now there are three gates:

| Gate | Catches | Cost | When |
|------|---------|------|------|
| **Substrate probe** (v0.24.26) | Octree upload / encoding bugs | One compute dispatch + 256 sample CPU↔GPU compare | `UNENDLICH_OCTREE_VERIFY=1`, gated by env |
| **CPU reference + unit tests** (this ship) | Algorithm bugs (coord space, winding, indexing, bumpy logic) | Pure CPU; `cargo test` | Always, on every CI run |
| **Output-sanity probe** (this ship) | Output-side bugs that escape unit tests (e.g., a bug in only the GPU implementation) | One pass per dispatched batch over emitted mesh | `UNENDLICH_OCTREE_MESH_VERIFY=1`, gated by env |

## What to test tomorrow

1. **Run flat mesher mode 0 baseline** — confirm we can see a
   reference for visual quality. (We never actually finished the
   v0.24.27 visual test; fix3 fix-up was sent but visual outcome
   was not captured.)

2. **Run mode 2 with both verifications enabled**:
   ```
   UNENDLICH_GPU_MESHER=2 UNENDLICH_OCTREE_VERIFY=1 \
   UNENDLICH_OCTREE_MESH_VERIFY=1 \
     cargo run --release --bin unendlich-world --features render
   ```
   - The substrate probe should print `OctreeProbe: ... matched`.
   - The mesh-output probe should print no `octree-mesher: N
     mesh-invariant violations` warnings.
   - Throttled diagnostic prints every 10 seconds with a summary.
   - Terrain should render with bumpy tops on grass/dirt/sand —
     not flat axis-aligned cubes for those materials.

3. **Performance**: post-fix3, the headline v0.24.27 perf numbers
   (2.6× faster main pass; 2.3× faster total) should still hold,
   modulo a small overhead from the bumpy verts (we emit ~6.25×
   more verts on weatherable top faces only). Expect total perf
   to drop from 2.3× to maybe 1.8–2.0×; if it drops much more,
   the bumpy path's overdraw is the suspect.

4. **Visual approval ("potato test")**: subjective judgment. Does
   it look closer to the Camp 1.5 weathered aesthetic the §6.1
   rewrite committed to? If yes, Ship B-prep landed. If no, the
   `bumpy_height` parameters can tune (amplitude, octave count,
   frequency) without changing the architecture.

## What's deferred to a later ship

- **Per-block weathering via instance buffer** (Ship B proper).
  Currently the mesher decides bumpiness from block_id only;
  freshly-placed grass looks the same as ancient eroded grass.
  Ship B proper adds a GPU instance buffer carrying per-block
  weathering state (parallel to the renderer's existing instance
  buffer for plants).

- **Side-face top-edge subdivision.** Right now a bumpy top dips
  below the side face's top edge, creating a tiny visible step.
  Fix: when a weatherable block's top face is bumpy and a side
  face is also exposed, subdivide the side face's top edge to
  match the bumpy top corners. Small change; deferred for after
  visual confirmation that the basic version reads well.

- **Climate tinting** (currently uniform color per block-id).
  Mode 0 has climate-based color variation; mode 2 ports it from
  the CPU mesher when the bumpy version is locked in.

- **Cross-chunk neighbor lookups** (v0.24.29 candidate). Still
  open-boundary; faces emit at chunk borders that would be
  occluded by the neighbor chunk's blocks. Visible as light
  z-fighting at chunk seams.

- **Shared OctreeBufferPool between renderer and mesher**
  (v0.24.30 candidate). Right now the mesher has its own octree
  buffer separate from the renderer's. Unifying eliminates one
  copy and one unverified buffer.

## How to revert if visual reads badly

The bumpy path is purely additive. To revert just the bumpy
behavior while keeping the falsification gates and consolidated
v0.24.27 fixes, change two lines in
`chunk_mesh_octree.comp`'s +Y face branch:

```glsl
if (is_weatherable(self_block)) {            // <-- delete this branch
    emit_bumpy_top_quad(...);
} else {
    emit_quad(..., c010, c011, c111, c110, color);
}
```

becomes

```glsl
emit_quad(..., c010, c011, c111, c110, color);
```

and rebuild the SPV. Everything else (CPU reference, output probe,
diagnostic throttling) remains valid even with the flat path,
because the invariant checker doesn't assume bumpy.
