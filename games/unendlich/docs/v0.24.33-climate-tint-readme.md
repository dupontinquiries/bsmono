# v0.24.33-climate-tint

## Tagline

Per-chunk temperature + humidity → shader modulates grass, leaves,
dirt, sand colors. Closes the biggest visual gap between mode 2
(octree GPU mesher, formerly uniform) and mode 0 (CPU mesher,
climate-aware).

## Status

Built autonomously. Compiles in head (Rust struct size assertion
holds; GLSL compiles cleanly). Not yet built or run. Stacked on
v0.24.32-pool-prewarm.

## What this ship does

Previously the GPU mesher's `color_for_block(block_id)` returned
a single hardcoded color per block_id. Every grass chunk had
identical green. Visual reads as "Lego world" — no biome variation.

Now each chunk gets a per-chunk temperature and humidity sample
from `WorldModel` (computed at the worker thread when building
the mesh request, taken at chunk center). Those flow through
`OctreeGpuMeshRequest` → `OctreeBatchInput` → `ChunkMetaGpu`
into the shader.

The shader's new `apply_climate_tint(base, block_id, t, h)`
modulates color:

| Block        | Cold/Dry behavior        | Warm/Humid behavior      |
|--------------|--------------------------|--------------------------|
| Grass        | Yellow-tan               | Deep saturated green     |
| Oak leaves   | Dry brown                | Lush green               |
| Dirt         | Cool grey (base)         | Iron-red shift           |
| Sand         | Neutral cream            | Slight red shift         |

All other blocks pass through unchanged.

## ChunkMetaGpu struct size

Stayed at 64 bytes by replacing the two `_pad2, _pad3` u32s
introduced in v0.24.30 with `temperature: f32, humidity: f32`.
Rust still asserts `[(); 64] = [(); sizeof::<ChunkMetaGpu>()]`;
GLSL std430 layout unchanged from v0.24.30 except those two
slots are now declared as `float` instead of `uint`.

## Data path

```
Worker thread (Near LOD):
    req.world_model.temperature(center) → temperature: f32
    req.world_model.humidity(center)    → humidity: f32
        ↓
OctreeGpuMeshRequest { ..., temperature, humidity }
        ↓ (channel)
Octree dispatcher: build OctreeBatchInput { ..., temperature, humidity }
        ↓
mesh_chunks_one_submission → dispatch_and_readback
        ↓
ChunkMetaGpu { ..., temperature: f32, humidity: f32 }
        ↓ (GPU SSBO)
Shader: color = apply_climate_tint(color_for_block(block_id),
                                    block_id, meta.temperature, meta.humidity)
```

## Performance impact

Per chunk submitted: 2 WorldModel function calls. WorldModel's
temperature/humidity are blended noise field samples — typically
sub-microsecond. The CPU mesher path that this replaces was
calling these PER BLOCK (32³ = 32768 calls per chunk in worst
case). So this is roughly 16000× cheaper than the legacy path,
at the cost of one-color-per-chunk fidelity instead of one-
color-per-block.

## Per-chunk vs per-block fidelity

The CPU mesher (mode 0) samples climate per block, giving
smooth gradients within a chunk. Mode 2 with this ship samples
once per chunk. Visible difference:

- Within a chunk: uniform color (no within-chunk gradient).
- At chunk boundaries: visible color step if temperature/humidity
  gradient crosses the seam.

For most viewing distances this is acceptable — chunk seams are
32 blocks apart, which is roughly the eye's color-discrimination
limit at typical view distances. Close-up examination will
reveal the per-chunk granularity.

Next step toward per-block fidelity: either
1. Port WorldModel's noise functions to GLSL (substantial — the
   blended noise field has multiple octaves and region
   selection), OR
2. Upload a climate field SSBO sampled at integer-block grid
   intervals; shader interpolates.

Filed for follow-up. Per-chunk is the right foundation.

## Failure modes

- WorldModel unavailable → fallback (0.5, 0.5). Lerp factor 0.5
  yields a middle-ground tint, neither lush nor dry — acceptable
  visual.
- NaN/Inf from WorldModel → `clamp(t, 0.0, 1.0)` and
  `clamp(h, 0.0, 1.0)` before mixing. Saturates to one extreme
  instead of propagating NaN through the color path.
- Block_id not in `apply_climate_tint`'s switch → returns base
  color unchanged. No regression for any non-listed block.

## Rollback

The fields are additive in the OctreeMeshRequest / OctreeBatchInput
chain. To revert just the tint:
- In shader, delete `apply_climate_tint` and the call line in main.
- Optionally revert ChunkMeta's two trailing fields back to `_pad2, _pad3` (or leave as climate fields and just don't read).

To fully revert all the way to v0.24.32 form:
- Reverse the OctreeBatchInput / OctreeGpuMeshRequest field
  additions.
- Revert ChunkMetaGpu and the GLSL struct.
- Remove worker's climate computation in meshing_pool.rs.
- Rebuild SPV.
