# v0.24.12-bench-extract-fix — fix bench extract-time bug

Surgical fix. Engine code unchanged. Single-section bench change.

## What was wrong

v0.24.11's bench output included:

```
─ SurfaceRun compression analysis ─
  records:  149494     (extract: 4138458 us total, 114957 us/chunk avg)
  runs:      18274     (extract: 4154420 us total, 115400 us/chunk avg)
```

**Both "extract" lines reported ~115ms per chunk.** That was the
chunk generator (full noise + biome + layers) running inside the
timing loop, not the extractor:

```rust
let t = Instant::now();
for (coord, _) in &all_inputs_owned {
    let chunk = gen.generate_chunk(*coord);  // ← ~115ms here
    total_records += extract_surface(&chunk).len();
}
```

So `records_extract_us` was really `gen.generate_chunk × 36 +
extract_surface × 36`. Generator dominates by 1000×, swallowing
the actual extract cost.

The compression ratio (8.18×) and average run length (9.04 blocks)
in the same output are correct — those are data, not timing. Only
the extract-time lines were meaningless.

## What's fixed

Pre-generate chunks once at the top of the analysis section, then
time only the extractors against the cached chunks:

```rust
let pre_chunks: Vec<Chunk> = all_inputs_owned.iter()
    .map(|(coord, _)| gen.generate_chunk(*coord))
    .collect();

let t = Instant::now();
for chunk in &pre_chunks {
    total_records += extract_surface(chunk).len();
}
let records_extract_us = t.elapsed().as_micros();
```

Also added: a "runs extract overhead vs records" ratio so we can
see how much more expensive the 6-pass run extractor is than the
single-pass record extractor.

## Predicted result

Per-chunk: `extract_surface` walks 32³ = 32K cells once, ~few hundred
us. `extract_surface_runs` walks 32³ × 6 face directions ≈ 200K
iterations, ~1-2 ms per chunk.

Total for 36 chunks: extract_surface ~10ms, extract_surface_runs
~50ms. These are CPU-side costs that the GPU path pays before
dispatch — included in the honest "total GPU path cost" but not
currently in the v2/v3 timing numbers.

If extract_surface_runs really is 50ms, that's much bigger than v3's
GPU dispatch time (1.8ms). **The runs extractor becomes the bottleneck
of the GPU runs path.** Worth knowing before production wiring.

## What this ship does NOT do

- No engine code changes.
- Doesn't fix other bench inefficiencies (the bench still
  regenerates chunks redundantly in 4+ other sections totaling
  ~20s of wasted CPU work on startup). Filed for later cleanup.
- Doesn't change any measured speedup ratios — those numbers were
  always correct; only the extract-cost line was wrong.

## What to look at in the output

The "SurfaceRun compression analysis" section will show real extract
times. Expected:

```
  records:  149494     (extract: ~5000-15000 us total, ~150-400 us/chunk avg)
  runs:      18274     (extract: ~30000-60000 us total, ~800-1700 us/chunk avg)
  compression ratio (records/runs): 8.18×
  avg run length: 9.04 blocks
  runs extract overhead vs records: ~3-6×
```

If runs extraction is really 30-60ms for 36 chunks, the GPU runs
path's TOTAL cost (extract + dispatch) is closer to 32-60ms, not
1.8ms. That fundamentally changes the v3 vs CPU comparison.
