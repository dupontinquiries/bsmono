# v0.24.NEXT+8 — weather physics: rain ↔ snow, flicker, storm wind

## What

Real weather *physics* on top of the v0.24.NEXT+5 atmospheric weather:
precipitation now splits into rain vs snow by temperature, with visibly
distinct skies, plus a lightning flicker and storm wind. All still
flag-gated by the existing `UNENDLICH_WEATHER=1` — no new flag.

### Rain ↔ snow phase (the centerpiece)

`weather::sample` now uses the `temperature` it already received (was
ignored). `snow_fraction(temperature)` = `1 − smoothstep(0.25, 0.38, T)`
on the climate `[0,1]` scale — cold air freezes the precipitation. A
storm is rain when warm, snow when cold, sleet in the band.

Visually distinct, because rain and snow scatter light oppositely:

- **Rain (liquid)** darkens sky/sun/ambient + thickens fog — overcast
  wet gloom (unchanged behaviour).
- **Snow (frozen)** *brightens*: sky lerps toward a bright neutral
  white-grey, ambient lifts (snow scatters light), fog thickens
  (white-out), sun softens. A snowstorm whites out; a rainstorm darkens.

The background clear color already tracks the modulated sky, so the
horizon whitens in snow and darkens in rain automatically.

This ties the climate fields together: cold biomes / high altitude →
snow; warm lowlands → rain — emergent from temperature, no scripting.

### Lightning: flicker + rain-only

- Each strike now emits a bright main pulse plus a fainter, faster echo
  `FLICKER_GAP` later — the characteristic double-flash.
- Lightning is gated to the **liquid** fraction, so snowstorms don't
  flash (thundersnow is rare; this reads correctly).

### Storm wind

Total precipitation lifts `AtmosphereParams.wind_magnitude` (the
shader's fog-shimmer amplitude), so storms read as turbulent rather than
still. Additive and modest.

## Why it's low-risk

- **Same flag, default off.** With `UNENDLICH_WEATHER` unset, nothing
  changes. The split only restructures the existing modulation.
- **Pure, tested state.** Snow/flicker logic is in `weather.rs` with
  tests: `snow_fraction_goes_cold_to_warm`,
  `liquid_and_snow_split_sums_to_precipitation`,
  `no_lightning_in_a_snowstorm`, `warm_storms_can_still_flash`. Flash
  stays bounded `[0,1]`.
- **Render change is the same local-copy modulation** as before, just
  split into rain/snow branches + a wind bump. The bin is untouched.
- The wind bump is the one value whose exact shader use I can't see
  (it's a shimmer amplitude per the field doc); it's additive/modest, so
  worst case is a slightly-too-shimmery storm — tune the `0.6` factor.

## Known limits (in CLIMATE_PATH.md)

- **Snow is driven by base climate temperature**, not the seasonal tint.
  Cold biomes/altitudes snow; a temperate-biome storm won't snow just
  because it's "winter" until the seasonal delta is shared into the
  weather temperature (needs a common world-tick source between the
  renderer and the season clock). Filed.
- Still atmospheric only — no snow *accumulation* on the ground (that's
  the `Snow`/`SnowBlock` placement, a worldgen/sim step), no particles.

## Files changed

- `crates/unendlich-engine/src/world/weather.rs` — `snow_fraction`,
  `WeatherState.snow_fraction` + `liquid_rain`/`snow_amount` helpers,
  lightning flicker + rain-gating, `sample` uses temperature. +4 tests
  (now 11 in the module).
- `crates/unendlich-engine/src/render/world_renderer.rs` — split the
  weather modulation into rain (darken) / snow (whiten) branches + storm
  wind bump.
- `scripts/sanity.sh` — 42 → 44.

## How to verify

```bash
./scripts/sanity.sh    # expect 44 passed / 0 failed
```

Playtest with weather on, then visit warm vs cold regions (or fly up a
cold mountain) during a storm:

```bash
... <your flag mix> ... UNENDLICH_WEATHER=1 \
  cargo run --release --bin unendlich-world --features render,gpu
```

Warm storm → dark wet overcast + lightning flicker. Cold storm → bright
white-out, no lightning, thicker fog. A/B by toggling `UNENDLICH_WEATHER`.
