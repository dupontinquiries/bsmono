# v0.24.2c.12-b — Cross-version compare + run-suite

Second half of the c.12 arc. Adds the cross-version compare features
the launcher was built for, plus the test-all button. The workspace
refactor from c.12a paid off here: all the comparison work landed in
`unendlich-launcher` without touching the engine.

## What's new

### 1. GPU/driver identity in result files

Every `.unendresult.json` now includes a `gpu_info` field:

```json
{
  "gpu_info": {
    "vendor_id": 4203,
    "device_id": 4132,
    "driver_version_raw": 4194304,
    "driver_name": "Asahi",
    "driver_info": "Mesa 25.0.0-devel...",
    "driver_hash": "drv-abc1234567890def"
  },
  ...
}
```

Captured at Vulkan context creation via `VkPhysicalDeviceProperties` +
the `VK_KHR_driver_properties` extension (available in Vulkan 1.2+
core). If the driver_properties extension isn't supported (older
drivers), `driver_name` and `driver_info` are empty strings but
`vendor_id` / `device_id` / `driver_version_raw` are still populated.

`driver_hash` is a short stable identifier (`drv-` + 16 hex chars,
FNV-1a over the composite identity). Used by `compare` to detect
driver-epoch drift.

**Backward compatibility:** result files from c.11 and earlier
(without `gpu_info`) still deserialize cleanly. The field is
`Option<GpuInfo>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`.

### 2. `unendlich-launcher compare`

Side-by-side diff table across multiple results. Two modes:

**Run-and-compare** (specifies versions to run):
```bash
unendlich-launcher compare tests/specs/rd2_smoke.unendtest \
    --versions @v0.24.2-c.7,@v0.24.2-c.10,@HEAD
```

**Load existing results** (skip running, just read .unendresult.json files):
```bash
unendlich-launcher compare --results \
    old_run.unendresult.json new_run.unendresult.json
```

Output format:

```
Metric             | result_old | result_new | result_newer_driver
-------------------+------------+------------+--------------------
acquire_p50_ms     | 4.06       | 0.016      | 0.014
shadow_p50_ms      | 1.69       | 0.678      | 0.500
wait_fences_p99_ms | 175.0      | 18.20      | —
-------------------+------------+------------+--------------------
driver_hash        | drv-abc123 | drv-abc123 | drv-def456
assertions         | PASS       | PASS       | PASS

⚠  Driver hashes differ across compared results. Cross-version
   perf comparisons across a driver epoch boundary may be
   misleading. Consider re-running the older versions under
   the current driver to fill gaps within a single epoch.
```

Key behaviors:

- **Missing metrics show as `—`** — explicit gap, not silent omission.
- **Missing columns (failed to load/run) show as `—` throughout** — not zeroed.
- **Driver-mismatch warning** appears when any pair of present
  driver hashes differs.
- **Pure separation:** `build_compare_report` is a pure function over
  the data; `render_compare_report` is pure text rendering. Library
  consumers (future GUI/TUI) can build the same report and render
  differently.

Exit codes:
- `0` — all results loaded, all assertions passed.
- `1` — all results loaded, ≥1 assertions failed.
- `2` — ≥1 column couldn't be loaded (file missing, JSON malformed,
  build/run failed).

### 3. `unendlich-launcher run-suite`

Run every `.unendtest` under `tests/specs/` (or `--specs-dir <DIR>`)
against `@HEAD` (or `--version <REF>`):

```bash
unendlich-launcher run-suite
# or
unendlich-launcher run-suite --version @v0.24.2-c.10 --specs-dir tests/specs
```

Output:

```
unendlich-launcher run-suite
  specs dir: /home/.../tests/specs
  version:   @HEAD

Commit: abc1234567890def...

  PASS  rd2_fifo_compat
  PASS  rd2_smoke
  FAIL  rd8_fifo_compat
  FAIL  rd8_immediate
  FAIL  rd8_low_upload
  FAIL  rd8_smoke

Total: 2 pass, 4 fail, 0 error
```

A failed spec doesn't abort the suite — the suite runs every spec
and reports the totals at the end. Errors (couldn't build, couldn't
run) are distinct from assertion failures.

Exit codes:
- `0` — every spec ran successfully and passed assertions.
- `1` — at least one spec failed or errored.
- `2` — setup error (couldn't resolve version, couldn't build binary,
  couldn't read specs dir).

### 4. Smoke script: optional suite mode

`commands/launcher_smoke.sh` accepts `--suite`:

```bash
./commands/launcher_smoke.sh           # single rd2_smoke
./commands/launcher_smoke.sh --suite   # everything under tests/specs/
```

The single-spec mode stays the default since it's fast (~5s) and
useful for "is everything wired" smoke tests after a zip update.

## Validation workflow

```bash
# Sanity: build everything, run unit tests across the workspace.
cargo test --workspace

# Smoke: launcher works end-to-end at HEAD.
./commands/launcher_smoke.sh

# Suite: every spec passes at HEAD (slow first time).
./commands/launcher_smoke.sh --suite

# Compare: HEAD vs a tagged historical version (requires the older
# tag to exist in your repo).
./target/release/unendlich-launcher compare tests/specs/rd2_smoke.unendtest \
    --versions @v0.24.2-c.10,@HEAD

# Compare existing results (no rebuild):
./target/release/unendlich-launcher compare --results \
    ~/.unendlich/runs/r-*/result.unendresult.json
```

The compare-from-files mode is particularly useful when re-running
old versions is expensive: you cache the runs once, then compare
freely without re-building anything.
