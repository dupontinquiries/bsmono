# v0.24.15-parallel-extract — parallel extract experiment

Bench-only ship. Engine code unchanged.

## What this measures

v0.24.13's hardware result revealed a gap: v3 honest total (12ms)
loses to CPU naive parallel (5.5ms) by 2.2×. The extract step
(10ms) is the bottleneck.

This ship parallelizes the extract step in the bench across 4
workers (POOL_WORKERS, matching production MeshingPool). Tests
whether extract scales linearly.

## Predictions

If extract scales linearly (best case):
- records par ~2,000 us (was 7,000)
- runs par ~3,000 us (was 10,000)
- v3 honest (par): ~5,000 us
- v3 vs CPU naive parallel: ~1.1× (slight win)
- v3 vs MeshingPool: ~5.5×

If extract scales poorly (e.g. ~2×):
- records par ~3,500 us
- runs par ~5,000 us
- v3 honest (par): ~7,000 us
- Still loses to CPU naive parallel

Either way the GPU path's CPU-side framing cost becomes visible
and we know what to optimize next.

## What this ship does NOT do

- No engine code changes.
- No new tests (parallel extraction is straightforward thread
  spawning; correctness verified by runtime assert that parallel
  and sequential extractors agree on output counts).
- No production wiring. MeshingPool still uses the CPU greedy+sky
  path; this only measures what _would_ happen if we wired GPU in.
