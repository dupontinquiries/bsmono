# v0.24.2c.12-e — Housekeeping + triage + boot-mode logging

Small ship with six focused fixes. No new architecture, no perf work —
just paying down debt that surfaced during c.12-c validation and
making the launcher's day-to-day ergonomics better.

## What's new

### 1. Hermetic worlds for spec runs

**Before c.12-e:** every spec run accumulated game state in `./worlds/default/`.
Re-running the same spec started from an already-edited world, so successive
runs weren't measuring the same workload. Subtle determinism leak.

**Now:** when `--test-spec` is passed (i.e., a launcher-driven run), the
world persists under `~/.unendlich/runs/<run-uuid>/world/` instead. Each
run gets a fresh world derived from the seed. Interactive runs (no spec)
still use `./worlds/default/` to preserve play state across launches.

This unblocks meaningful cross-version `compare` from here on out.

### 2. Boot-mode per-frame logging

**Before c.12-e:** the engine emitted one aggregated `frame_window` event
per 1-second window. Startup jank (first paint, first chunks, mouse
capture) got averaged into a single window summary.

**Now:** the first ~3 seconds of each run emit ONE `frame_window` event
per frame, tagged `mode: "boot"`. After that, normal 1Hz aggregation
resumes, tagged `mode: "steady"`. Cost: ~90KB extra in events.jsonl per
run.

What this gives us: instead of "first second was 16fps avg," we see
"frame 0 took 200ms (first paint), frames 1-3 took 130ms (chunk gen),
frames 4-29 were fine." The shape of the warmup curve becomes visible.

### 3. Post-run incident triage

**New:** after every spec run, the launcher reads the events.jsonl,
examines `mode: "steady"` frame_window events, and decides:

- **Healthy run** (every steady-window p50 below threshold): events.jsonl
  is deleted to save disk. The result.unendresult.json alone is enough.
- **Incident** (any steady-window p50 above threshold): events.jsonl is
  kept for forensic analysis.

An `incident_summary.json` is written either way, so the triage decision
is preserved even when events are deleted.

Threshold defaults to **33ms p50** (= ~30fps); override via
`UNENDLICH_TRIAGE_THRESHOLD_MS`. Boot-mode events are excluded — early
warmup is expected to be slow.

The CLI's "Run complete" output now shows the triage verdict:

```
┌─ Run complete ─────────────────────────────────
│ commit:     2fa0e44...
│ result:     /home/.../runs/r-.../result.unendresult.json
│ events:     (deleted — run was healthy, worst p50=2.7ms)
│ triage:     healthy (5 steady windows under 33ms threshold)
│ exit:       Some(0)
│ assertions: PASSED
└────────────────────────────────────────────────
```

Or, when something stalls:

```
│ events:    /home/.../runs/r-.../events.jsonl
│ triage:    INCIDENT — worst p50 was 87.4ms > 33ms threshold
│            (4 steady windows examined)
```

### 4. `.gitignore` for engine-produced files

Added `/worlds/`, `run_summaries.txt`. These now never make it into
git status from manual `cargo run` invocations. (Spec runs already
write to `~/.unendlich/` and don't pollute the repo.)

### 5. Scripts work from any cwd

`commands/launcher_smoke.sh`, `commands/update_from_claude_zip.sh`,
and `commands/tag_current_version.sh` all now resolve their location
via `BASH_SOURCE` and `cd` into the repo root automatically.

Before: had to `cd ~/Code/unendlich-development/unendlich-game` first.
After: run from anywhere.

### 6. `unendlich-analyze optimize` subcommand

New subcommand that reads a `.unendresult.json` file and prints two
ranked tables:

```
Where time is spent (ranked by mean contribution)
───────────────────────────────────────────────────
cat      zone                mean_ms     p50_ms     p99_ms     max_ms   % of cat
cpu      wait_fences           5.490      1.570    126.760    224.630        84%
gpu      total                 5.380      1.590    125.410    235.680          —
gpu      shadow                2.900      0.670     85.310    120.900        54%
gpu      main                  2.100      0.730     44.440    186.520        39%
...

Tail-latency volatility (ranked by p99/p50)
───────────────────────────────────────────
cat      zone                 p50_ms     p99_ms    p99/p50
gpu      shadow                0.670     85.310     127.3×
cpu      wait_fences           1.570    126.760      80.7×
gpu      main                  0.730     44.440      60.9×
...
```

The first table tells you **where to spend optimization effort** (mean
contribution). The second tells you **where hidden spikes are dragging
the tail** (p99/p50 ratio).

This is what the box plots in the binary's log already show, but ranked
across all zones at once. Cross-zone comparison was previously a manual
read.

Usage:
```bash
unendlich-analyze optimize ~/.unendlich/runs/r-abc123.../result.unendresult.json
```

## Files changed

### Engine
- `crates/unendlich-engine/src/bin/unendlich_world.rs`:
  - World path is per-run when `--test-spec` is set.
  - Emits per-frame `frame_window` events tagged `mode: "boot"` for
    the first 3 seconds.
  - Existing 1Hz aggregated events now tagged `mode: "steady"`.

### Launcher
- `crates/unendlich-launcher/src/lib.rs`:
  - New `TriageSummary` type + `run_triage()` function.
  - `RunOutcome` extended with `triage: Option<TriageSummary>`.
  - `run_spec()` calls triage after the binary exits.
  - 6 new unit tests for the triage logic.
- `crates/unendlich-launcher/src/bin/unendlich_launcher.rs`:
  - "Run complete" output now shows triage verdict.
- `crates/unendlich-launcher/Cargo.toml`: added `serde` for the
  triage summary's derive.

### Analyze
- `crates/unendlich-analyze/src/main.rs`:
  - New `optimize` subcommand.
  - Dispatcher refactored so subcommands that don't need events.jsonl
    don't try to read it.

### Commands
- `commands/launcher_smoke.sh`: cwd-independent via SCRIPT_DIR.
- `commands/tag_current_version.sh`: same.
- `commands/update_from_claude_zip.sh`: same.

### Misc
- `.gitignore`: `/worlds/`, `run_summaries.txt`.
- All four crate versions bumped to `0.24.2-c.12-e`.

## Validation workflow

```bash
cd ~/Code/unendlich-development/unendlich-game

# Apply c.12-e.
./commands/update_from_claude_zip.sh unendlich-v0.24.2c.12-e.zip
git add -A && git commit -m "Update to v0.24.2-c.12-e"
./commands/tag_current_version.sh

# Smoke. New output should show triage info.
./commands/launcher_smoke.sh

# Full suite.
./commands/launcher_smoke.sh --suite

# Try optimize on the result file.
unendlich-analyze optimize ~/.unendlich/runs/r-.../result.unendresult.json

# Hermetic worlds check: re-run the smoke twice in a row.
# Should now produce identical results (within timing noise) because
# neither run starts from edits made by the other.
./commands/launcher_smoke.sh
./commands/launcher_smoke.sh
diff <(jq .stats ~/.unendlich/runs/r-A/result.unendresult.json) \
     <(jq .stats ~/.unendlich/runs/r-B/result.unendresult.json)
```

## What's NOT in c.12-e

- **Ring buffer in-engine forensic capture.** Deferred (filed in
  DESIGN_NOTES). Trigger condition: when we have a test matrix large
  enough that per-frame data of incidents is diagnostically valuable.
- **`--clean-world` / `--new-world-gen` spec flag.** Not needed —
  hermetic worlds are now the default for spec runs (every run is
  effectively a fresh world).
- **Distro detection / dep installation in launcher.** Filed for
  c.12-d if we decide to ship it as opt-in suggestion. Today: just
  the dlopen-and-suggest design proposal in DESIGN_NOTES.
