# v0.24.11-batch-64 — MAX_BATCH_CHUNKS raised + env override

Quick configuration change. Increases `MAX_BATCH_CHUNKS` from 16 to
64. At 36 chunks (the bench size), v0.24.10 used 3 submissions
(16+16+4); v0.24.11 uses 1 submission. The ~550us dispatch floor
is paid once, not three times.

Also adds runtime env var `UNENDLICH_GPU_MESH_BATCH` (1..=64) to
cap actual chunks per submission. Buffers are still sized for 64;
the env var only limits the in-loop chunking. Lets you sweep batch
sizes on hardware without recompiling.

## Predicted effects

If AGX firmware properly pipelines 64 dispatches within one cmd
buffer: v2 should drop from ~5.5ms to ~3-4ms for 36 chunks. v3
(runs) should drop proportionally.

If AGX firmware serializes dispatches: not much change (we already
saw 5× speedup at batch=16, so dispatches ARE running concurrently
within a cmd buffer, otherwise we'd have seen ~1×).

## Memory cost

Buffers grow from ~24 MB to ~96 MB:
- Records: 64 × 16K × 16B = 16 MB
- Vertices: 64 × 43K × 24B = 64 MB
- Indices: 64 × 64K × 4B = 16 MB
- Counters: 64 × 16B = 1 KB

On M2 unified memory, trivial. Persistent HOST_VISIBLE allocation
held for the mesher's lifetime.

## Test sweep recommendation

After running the bench at default (batch=64), try:

```bash
UNENDLICH_GPU_MESH_BATCH=1  cargo run ... --bin gpu-mesh-bench
UNENDLICH_GPU_MESH_BATCH=8  cargo run ... --bin gpu-mesh-bench
UNENDLICH_GPU_MESH_BATCH=16 cargo run ... --bin gpu-mesh-bench
UNENDLICH_GPU_MESH_BATCH=32 cargo run ... --bin gpu-mesh-bench
UNENDLICH_GPU_MESH_BATCH=64 cargo run ... --bin gpu-mesh-bench
```

The v2/v3 total times should drop as batch size rises, with
diminishing returns past the point where compute time dominates
the dispatch floor.

## Honest concerns

1. **96 MB persistent HOST_VISIBLE allocation** is bigger than I'd
   pick for a production-shipped engine. v3+ should use DEVICE_LOCAL
   for output buffers (the renderer needs them eventually) and
   smaller HOST_VISIBLE staging. Filed for later.

2. **Larger batches mean longer fence-waits.** If GPU work for
   64 chunks takes 6ms, the caller blocks for 6ms. Production
   wiring (Layer A.3) will need async dispatch regardless of batch
   size; the larger batch makes async even more important.

3. **The bench is single-shot.** It runs once. Each batch-size
   sweep is a fresh process start. AGX firmware might warm up over
   multiple runs — the first batch could be slower than steady-state.
   v0.24.12 could add a warmup phase, filed.
