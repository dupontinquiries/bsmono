# shocovox → fleet: what actually transfers

Reference: **Shocovox** (`shocovox-main`, v0.11.1) — "Shady Octree Of Voxels with Ray
Marching", a sparse voxel octree raytraced in WGPU. Leaves hold 8³ voxel *bricks*
rather than single voxels, which is what makes its mixed-resolution compression work.
Upstream is archived in favour of VoxelHex.

Everything below is anchored to code on both sides. Where a claim is **measured** the
benchmark is in `maintenance/perf/` and reproduces with plain `rustc -O`. Where it is
**reasoned**, it says so.

## Summary

## The techniques worth taking from shocovox

1. **Ray→node occupancy bitmask LUT** — `RAY_TO_NODE_OCCUPANCY_BITMASK_LUT[64][16]`
   (`assets/shaders/viewport_render.wgsl:1156`, generated by `src/spatial/lut.rs`).
   Indexed by position-in-brick × ray-direction octant, it yields a 64-bit mask; one
   AND against a node's occupancy bitmap answers "can this ray hit anything in here"
   without descending.
2. **Bricked leaves** — a leaf covers 8³ voxels contiguously instead of one.
3. **Bit-packed traversal stack** — `node_stack_meta` (`viewport_render.wgsl:110-167`)
   keeps count and head index in one `u32`; the 4-deep stack stays in registers.
4. **Branchless octant hash** — `hash_region` (`src/spatial/math/mod.rs:11`) is
   explicitly rewritten branch-free, with the branchy original left in a comment.
5. **DDA with hoisted scale factors** — `get_dda_scale_factors` once per ray, then
   cheap sibling steps (`dda_step_to_next_sibling`).
6. **GPU-driven residency** — `set_node_used` / `set_brick_used` / `request_node`
   (`viewport_render.wgsl:222-292`) mark touched nodes with atomics so the CPU can
   evict and stream against real usage rather than a guess.

## unendlich — the one measured win

`games/unendlich/crates/unendlich-engine/src/shaders/chunk_mesh_octree.comp`

The mesher's `octree_sample` (`octree_sample.glsl:63`) is a **point query**: it
restarts at the root and descends up to `OCTREE_DEPTH+1` levels, each level a
*dependent* SSBO load. Cost is dominated by that dependency chain, not arithmetic.

`find_greedy_run` (`chunk_mesh_octree.comp:770`) extends a greedy-meshing run and calls
`octree_sample` **from the root on every step** (line 787), up to 32 times.

The fix is already in the same file. The halo-fill loop at line 930 uses
`octree_sample_ext`, which additionally returns the covering leaf's extent, and caches
it — its own comment reads *"uniform regions (most of a chunk) collapse a 4-cell run to
a single descent"*. `find_greedy_run` never got that treatment. Since every cell inside
a uniform leaf holds the same block, a run can jump straight to the leaf's far edge.

Measured on a terrain-like 32³ chunk (solid below a rolling surface, air above — the
case that collapses an octree well), counting descents, which is hardware-independent
and is what the GPU cost tracks:

```
nodes=6945 (a fully-split 32^3 tree would be 37449)
current (root each step)   descents=   497969  (run extents summed: 484615)
leaf-extent reuse          descents=   228480  (run extents summed: 484615)
```

**54% fewer descents, with byte-identical run extents** — it is an optimization, not a
behaviour change. `maintenance/perf/bench_octree_descents.rs`.

Two caveats worth stating. The count includes one unavoidable `sample_ext` per cell in
both columns, so the saving *within the run loop* is proportionally larger than 54%.
And the win scales with how uniform the terrain is: a maximally noisy chunk collapses
to no leaves and both columns converge.

`sample_or_neighbor` at line 264 has the same shape, and the AO sampler
(`chunk_mesh_octree.comp:277+`) likewise re-descends per sample.

## unendlich — the structural gap

unendlich's node is 40 bytes: `packed_header`, `last_modified_tick`, `children[8]`
(`octree_types.glsl:54`). There is **no occupancy summary**, so "is anything solid in
this subtree" can only be answered by descending it. Bits 27..8 of the header are
documented as reserved and zero.

Shocovox carries a 64-bit occupancy bitmap per node and tests it against the LUT mask,
so an empty or ray-missed subtree costs one AND. For `octree_probe.comp` and any future
raymarch this is the difference between walking the tree and skipping it.

Reasoned, not measured — it changes the wire format (40 → 48 bytes/node, +20% octree
VRAM) and both the GLSL and its CPU twin `world/octree.rs` would have to move in
lockstep, which `octree_types.glsl` explicitly warns about. Worth prototyping behind the
existing falsification probe, which already caught a rebasing bug on this exact path.

## soldier — a negative result, measured

`games/soldier/src/sightline.rs`. `analyze` caps its sample set at 260 and does the full
upper triangle — 33,670 LOS rays — each a Bresenham walk (`has_los`, line 69) testing
`level.cell()` and a `tall: Vec<bool>` per tile.

That looks like a textbook case for shocovox's empty-space skipping. It is not.

```
                128²      256²      512²     1024²
naive          44.5ms    46.5ms    55.0ms    50.9ms
coarse-skip    65.6ms    69.0ms    70.9ms    71.0ms      <- 8x8 occupancy summary
bitset         45.1ms    47.6ms    49.3ms    49.7ms      <- bit-packed blockers
```

The coarse skip is **47% slower at 128² and still slower at 1024²**; identical results
throughout (asserted, not assumed). `maintenance/perf/bench_soldier_los.rs`.

**Why, and this is the transferable lesson:** occupancy skipping buys you the right to
*not perform a memory fetch*. On shocovox's GPU that fetch is a dependent SSBO read
costing hundreds of cycles, so skipping wins hugely. In soldier the per-tile test is an
L1-resident array index costing ~1 cycle, and the block-coordinate computation added per
step costs more than it saves. Rays also terminate on first blocker, so they are short
in exactly the dense maps where skipping would pay (visible pairs fall 115,680 → 2,820
as the map grows).

Bit-packing the blocker mask is a wash at 128² and worth ~10% only at 512² and above,
where 1 byte/tile stops fitting comfortably in cache. Soldier's maps are far smaller.

If soldier's LOS ever needs to be faster, the lever is the **O(m²) pair count**, not the
per-ray cost.

## logscope, paperbound, clawbound

Checked, not assumed — and little transfers:

- **logscope** `crates/logscope-egui/src/spatial.rs` is a 486-line helix layout plus an
  orbit projection, O(n) per frame over conversation nodes. No traversal to accelerate.
  `crates/gpu-gemm` is an 11k-line LLM GEMM that already has autotuned workgroup tiles
  and override-constant specialization; a voxel raytracer has nothing to teach it.
- **paperbound** `rust/paperbound-core/src/gpu.rs` is 181 lines of mesh→buffer export,
  not a hot loop.
- **clawbound** has no spatial, voxel or traversal code at all.

The one idea that *is* portable beyond unendlich is #6, GPU-driven residency: any
consumer that streams data to the GPU can have the shader mark what it actually touched
via atomics rather than the CPU predicting it. unendlich's chunk streaming is the
obvious candidate. Flagged as unverified — I did not trace its current residency policy.

## Order of work

1. `find_greedy_run` leaf-extent reuse — measured, behaviour-preserving, local to one
   function, and the pattern is already proven 130 lines below it.
2. Same treatment for `sample_or_neighbor` and the AO sampler.
3. Prototype the per-node occupancy bitmap behind the falsification probe.
4. Do **not** port occupancy skipping to soldier.
